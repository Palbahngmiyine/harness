# 검증 계약

[영문 원본](verification.md)이 기준이다. [공통 규칙](../AGENTS.md)과 함께 적용하고 정책 변경에는 [개선 절차](evolution.md)도 적용한다.

**CHK-001** 구현 전 관련 규칙 ID·입력 범위·관찰 가능한 출력/오류/상태/효과·필수 검사·도구 버전·완료 조건을 기록한다. 판정은 `PASS`·`FAIL`·`NOT_APPLICABLE(reason)`·`NOT_RUN(reason)`·`APPROVED_EXCEPTION(reference)`로 구분한다. 예외는 통과가 아니다. 미해결 필수 의무가 있으면 해당 완료/출시 주장을 보류한다.

**CHK-002** 의미·메모리·종료·자원·동시성 주장을 각각 근거에 연결한다. 신뢰 경계 기록에는 구성요소/버전·승인 계약·가정·검증기와 증명 의무·동적 테스트·빈틈·승인자를 적는다. 증명은 해당 모델의 명제에만 적용된다. 주석·lint·테스트는 서로 대체 가능한 보장 단계가 아니다.

**CHK-003** 변경 동작의 성공·실패·빈 값/부재/0/최소/최대/범위 밖 입력과 도달 가능한 모든 분기를 검사한다. 버그 수정마다 기준 구현에서 실패하고 수정 후 통과하는 재현 사례를 둔다. 오류 코드·mock 호출뿐 아니라 불변식과 실제 상태/효과를 검증한다. 무관한 관심사는 별도 테스트로 둔다.

**CHK-004** 코어는 실제 I/O 없이 검사한다. 독립 예제·속성/모델 검사와 최적화/승인 커널의 단순 순수 참조 모델을 사용한다. 생성기는 유효/무효 입력·상태 전이 이력을 대표하고 입력 유형 커버리지와 폐기 한도를 강제한다. 축소기는 속성의 관련 전제/실패 유형을 보존한다. 무효 입력 테스트에서 유효성 자체를 강제하지 않는다. 무의미하게 통과하는 속성과 구현으로 기대값을 계산하는 테스트를 거부한다.

**CHK-005** 자체 추상화나 대수적 리팩터링 전에 적용 법칙과 전제를 명시한다. 의미가 있을 때 항등·합성·결합·왕복·멱등을 검증하며 부동소수점·부분성·효과 순서에 거짓 법칙을 강제하지 않는다. 주소나 우연한 순회 순서와 독립적으로 정규화·결정적 직렬화를 검사한다.

**CHK-006** 코어 분기 커버리지 100%를 목표로 미도달·실제 도달 불가 사례와 근거를 나열한다. 복합 불리언에는 MC/DC를 적용한다. 변이 테스트로 분기·경계·상태 갱신 결함을 검사하고 동등 변이 등 살아남은 변이를 분류한다. 지표 때문에 방어 코드를 지우거나 단언을 약화하거나 경로를 제외하지 않는다. 도구 미지원은 자동 비해당이 아니라 `NOT_RUN`이다.

**CHK-007** 존재하는 의존성에 첫·N번째·연속·부분 성공 뒤 실패를 주입한다. 타임아웃·취소·할당/저장 공간 부족·부분 획득·정리 실패를 포함한다. 상태 일관성·소유권·실제 효과·남은 작업을 검사한다. 중복/오래된 확인 응답·원격 결과 불명을 확인한다. 로컬 롤백은 원격 롤백 검사가 아니다.

**CHK-008** 동시 시스템은 제어 스케줄과 스트레스·race·데드락·작업 누수·중복 효과·순서를 검사한다. 영속 시스템은 부분 쓰기·강제 종료·재시작·원자성 범위·안전 재시도·보상·복구를 검사한다. 파서/디코더는 panic·크래시·비종료·자원 고갈 퍼징을 수행한다. 입력·시드·실행 순서와 최소 반례를 영구 회귀 사례로 보존한다.

**CHK-009** sleep 기반 단언 대신 시계·난수 시드·스케줄을 제어한다. 퍼징/변이/스트레스에 입력·반복·메모리·시간 예산을 둔다. 유한 실행의 성공은 다른 실행의 부재를 증명하지 않는다. 필수 의무 충족 전에 예산이 끝나면 성공으로 재해석하지 말고 보고한다.

**CHK-010** 언어 프로파일의 타입/효과/의존성 검사와 분석기를 활용한다. 검사기 자체에 허용 예제와 의도적 위반을 넣는다. 부정 테스트는 무관한 컴파일 오류가 아니라 예상 원인으로 실패해야 한다. 간접 호출·중첩 가변 값·필수 문서 누락을 포함한다. 정규식/심벌 검색은 유용한 경보일 수 있지만 건전한 순수성 검사기로 부르지 않는다.

**CHK-011** 빠른 변경/커밋 전 검사와 전체 출시 전 검사를 분리한다. 전체 검증에는 해당하는 지원 주소/메모리/미정의/race/누수 분석을 호환되는 빌드로 실행한다. 지원 OS/아키텍처/엔디언/컴파일러/feature 행렬을 유지하고 비최적화·최적화·배포 결과를 비교한다. 필수 불변식은 배포에서도 유지한다. 미지원 타깃/도구 조합과 게이트 영향을 명시한다.

**CHK-012** 해당하는 실행 시간·할당·최대 생존 메모리·스택 깊이·처리량을 대표 입력으로 측정한다. 입력/도구 조건을 맞추고 필요한 단락 평가·스트림 생산성·오류 순서·정리를 보존한다. 빠른 커널 승인은 속도 수치뿐 아니라 변하지 않은 의미 판정 기준과 FP-007의 근거/승인을 요구한다.

**CHK-013** 출시 후보마다 전체 필수 회귀 검사를 재실행하고 변경된 사용자 흐름·실제 보안 영향·측정 성능·호환성·롤백/복구 단계에 방법/근거/판정이 있는 사람 체크리스트를 만든다. 체크리스트를 언급했다는 이유로 검토가 끝난 것이 아니다. 무관한 위험·승인 절차를 만들지 않는다.

**CHK-014** 이 패키지 검사기는 필수 경로·등록된 규칙 순서·비어 있지 않은 한 줄 규칙 도입부·번역 ID 대응·텍스트 형식·소스 줄 수를 검증한다. 링크 검사는 패키지가 사용하는 인라인 로컬 파일 경로와 ATX 제목 fragment를 대상으로 하며 임의 Markdown/HTML·외부 URL 가용성을 검증하지 않는다. 규칙 등록부 변경에도 규칙 변경과 같은 검토가 필요하며 ID 일치가 의미 약화를 막지는 못한다. 네이티브 예제는 선택한 계약과 적법한 비순수 반례를 보여준다. 번역 의미·전체 프로그램 순수성·사용 코드의 메모리 안전성·종료 증명·에이전트 성능을 보장하지 않는다. 각각 별도 검토나 미수행 활동으로 보고한다.
