# 근거 기반 재귀적 개선

[영문 원본](evolution.md)이 기준이다. [공통 규칙](../AGENTS.md)·[검증](verification.md)과 함께 적용한다. 공개 시작 사례: [평가 코퍼스](../evals/cases.ko.md).

**EVO-001** 재귀적 개선은 지침과 별도 범위에 포함된 적용 소프트웨어에 대해 제안·공격·수정·재검토를 유한하게 반복하는 절차다. 본 패키지는 이를 Markdown으로 설명하며 자동 실행 에이전트나 평가기가 아니다. 코드 변경·병합·배포·목표 변경의 추가 권한을 부여하지 않는다. 제안은 검토 데이터이며 문서 검토는 효과 실행이 아니다. 함수 재귀·고정점 의미론·반복 검토는 다른 개념이고 Haskell 논문이 이 절차의 수렴이나 에이전트 성능 향상을 증명하지 않는다.

**EVO-002** 후보별로 부모 개정·합의 요구·규칙 ID·검토 기준·관련 사례/출처·승인 범위를 고정한다. 실제 소프트웨어에는 언어/도구체계와 실행 판정기도 고정한다. 반증 가능한 가설 하나와 유한 예산을 정한다. 사용자가 다른 유한 예산을 정하지 않으면 실질적 수정 3회를 기본으로 한다. 기준 결과와 불확실성을 기록한다. 예산 한도가 미해결 발견을 통과로 바꾸지는 않으며 문서 검토에 가상의 빌드 환경은 필요하지 않다.

**EVO-003** 작고 안정된 계약과 순수 참조 관계를 기준으로 모듈을 변경한다. 한 번에 원인 하나를 바꾸고 공개 값·오류/상태/효과 이력·자원 의무를 비교한다. 호환 구현은 계약 뒤에서 반복 개선할 수 있다. 계약 변경은 승인·하위 호환 검토가 필요한 버전 있는 마이그레이션이며 숨은 리팩터링이 아니다.

**EVO-004** 공격과 방어 검토를 분리한다. Markdown에서는 정확한 규칙 문구·구체적인 상황·그 문구가 허용하는 잘못된 판단·규칙/출처에 근거한 반박 또는 수정을 제시한다. 수정 전후의 사례 판단을 추적하되 실행 테스트라고 부르지 않는다. 실제 소프트웨어에는 해당 실행 검증을 적용한다. 수정마다 인접 규칙·로딩 경로·번역을 재검토한다. 단일 어시스턴트의 순차 검토, 별도 세션, 독립 에이전트, 사람 검토 중 실제 구성을 밝히고 독립성을 꾸미지 않는다.

**EVO-005** 후보 판단 중 판정 기준과 기존 반례의 의도를 고정한다. 불편한 사례 삭제·의무 완화·제외 변경·근거 누락의 재분류로 통과시키지 않는다. 사용자가 범위를 명시적으로 바꾸면 번들 검사기 같은 범위 밖 전달 수단을 제거할 수 있으나 승인·사라지는 강제 수단·보존할 의무·새 검토 방식을 기록한다. 문서 검토가 동등한 실행 근거가 되거나 적용 소프트웨어 기준이 약해지는 것은 아니다. 잘못된 판정 기준은 근거·승인을 별도 기록해 수정하고 기준본과 후보를 같은 수정 기준으로 재검토한다.

**EVO-006** 코딩 에이전트 효과 향상 주장에는 별도로 승인한 조건 통제 평가, 개발 사례와 독립 비공개 문제, 반복 실행, 보존된 결과가 필요하다. 모델·설정·도구·저장소·예산을 맞추고 정확성·순수성/권한 위반·근거 보고·불필요한 복잡성·비용을 측정한다. 필수 품질을 통과한 뒤 비용을 비교한다. 서술형 사례와 문서 검토는 실행한 LLM 평가가 아니다. 문서 정확성 수정은 에이전트 영향 미측정을 명시하고 CHK-014로 완료할 수 있다. 지침 유지보수를 이유로 여기서 벤치마크 실행기를 생성하거나 평가 접근권을 구매하지 않는다.

**EVO-007** 후보는 승인 범위 안에서 명시한 검토 범위의 미해결 발견과 알려진 필수 계약 회귀가 없을 때만 완료 판정을 받을 수 있다. 반례·읽은 본문/출처 근거·결과·후보 식별을 보존하며 실제 실행한 경우에만 명령/실행 결과를 포함한다. 안심되는 검토 횟수를 채워서가 아니라 전체 범위 재검토에 문제가 없을 때 멈춘다. 후보 반복·진전 없음·미해결 상태의 예산 소진은 차단으로 보고한다. 지침 검토 완료는 병합 권한이나 적용 구현의 승인이 아니다.

**EVO-008** 부모 개정·복구 계획은 작업 맥락에 유지하고 주요 근거·결정·한계는 Git으로 추적하는 리뷰 파일 대신 작업 응답이나 PR 설명에 요약한다. 새 근거가 생기면 새로운 유한 주기를 시작하고 반례를 추가하며 영향 호출부·프로파일·번역·출처 연결·판정 기준을 재검토한다. 재사용할 반례의 의도는 날짜별 실행 이력 없이 사례 문서에 보존하고 과거 발견을 현재 인증처럼 제시하지 않는다. 양쪽 규칙 ID와 의미를 동기화하며 ID는 추적을 돕지만 동등성을 증명하지 않는다.

**EVO-009** 프로파일·공통 정책 검토에서는 해당 Markdown 사례를 논리적으로 확인한다. C 별칭/출력 쓰기, Rust 내부 가변성/암묵적 효과, Go 별칭/제로 값/취소/검증 한계, 즉시 실행 액션, 오버플로, 종료, 결과 불명, 평가 편법, 지침 누락을 포함한다. 정상 불변 클로저·값도 검토해 과잉 금지를 찾는다. 규범과 1차 출처에서 판정을 도출하고 사례의 기대 답안 자체도 공격한다. 이 검토가 개별 가변 커널을 승인하지는 않으며 FP-007의 프로젝트별 근거와 승인은 별도로 필요하다.

**EVO-010** 결과 요약은 실제 실행·읽기 검토만 수행한 항목·범위 밖·미검증을 구분한다. 범위 내 문제가 없다는 검토는 미래 코드 전체 보장·형식 증명·코딩 에이전트 향상 실증이 아니다. 대응 실행과 결과 보존 없이 벤치마크 향상을 발표하지 않는다.
