# Rust 함수형 프로그래밍 프로파일

[영문 원본](rust.md)이 기준이다. [공통 규칙](../AGENTS.md)·[검증](../fp/verification.md)과 함께 적용한다. 근거: [출처](../references/functional-programming.md).

범위: 이 문서는 서술형 정책이다. 아래 구현·실행 검증 의무는 실제 C/Rust 소프트웨어를 변경할 때 적용한다. 프로파일 문장만 수정할 때에는 CHK-014의 문서 검토를 사용한다. 예제 코드나 실행기는 본 패키지에 추가하지 않는다.

## 값·효과·합성

**RS-001** enum·불변 구조체·비공개 필드·스마트 생성자로 도메인 값을 표현하고 부재/예상 실패에는 `Option`/`Result`와 완전한 패턴 매칭을 사용한다. 역직렬화·FFI·마이그레이션·기능별 생성자도 검증한다. 외부 입력이나 예상 오류에 panic·무검사 인덱싱·`unwrap`을 쓰지 않는다.

**RS-002** 소유권·빌림·`&T`·`Send`·`Sync`·`Fn`·`const fn`·`#![forbid(unsafe_code)]`는 효과나 전함수성의 증명이 아니다. 명시적 입출력 계약과 검토된 의존성 경계를 유지한다. 가능하면 의미 코어 crate에 `forbid(unsafe_code)`를 사용하되 의존성까지 검사하거나 안전한 I/O도 배제한다고 주장하지 않는다.

**RS-003** 도메인 입력·결과·캡처에서 공유 `Cell`·`RefCell`·atomic·잠금·지연 가변 상태 등 `UnsafeCell` 기반 권한을 배제한다. `Arc<T>`는 공유 소유권만 제공하므로 `T`와 도달 가능한 상태를 검토한다. 도메인 페이로드와 연산이 계약을 지키는 불변 공유는 허용한다. 명시적인 FP-007 신뢰 라이브러리 계약하에서 할당·참조 횟수 관리는 가변 도메인 상태가 아닌 표현 세부사항일 수 있다. 포인터 식별성·참조 횟수·`Weak` 생존 여부로 도메인 결과를 결정하지 않는다. 사용자 할당기·사용자 소멸자는 계속 효과 검토가 필요하다.

**RS-004** `Fn`은 호출 방식을 제한할 뿐 관찰·변경 가능한 대상을 제한하지 않는다. trait 구현·반복자 콜백·연산자 오버로딩·`Deref`·`Clone`·포매팅·소멸자의 숨은 효과를 검토한다. `Cell`을 사용하는 클로저도 `Fn`을 구현하며 상태를 바꿀 수 있다. 제네릭 경계에는 검토된 의미 계약이 필요하고 trait 이름에서 순수성을 추론하지 않는다.

**RS-005** 계약이 명확해질 때 이름 있는 함수·반복자·`map`·`and_then`·`try_fold`·패턴 매칭을 합성한다. `collect::<Result<_, _>>()`는 즉시 실패하므로 독립 검증 오류 누적은 별도 설계가 필요하다. 관찰 가능한 순회 순서를 보존하고 해시 순회가 안정적이라고 가정하는 대신 결정적인 결과 순서/인코딩을 정한다. 실제 필요 없이 고차 종류 타입 흉내나 효과 런타임을 구현하지 않는다.

**RS-006** 불변 상태를 소비하거나 빌려 새 상태와 명령 데이터를 반환한다. 값 소비는 일부 별칭 문제를 줄이지만 효과를 배제하지는 않는다. 구체적인 I/O 핸들·런타임 접근·가변 서비스 객체는 도메인 판단 밖에 둔다. future/액션은 실제 코드가 언제 실행되는지 확인한다. polling과 drop도 효과를 낼 수 있다.

## 구현과 자원

**RS-007** 불변 의미 구현을 우선한다. 소유한 지역 변경·builder·arena·제자리 알고리즘은 자동 `mut` 예외가 아니라 FP-007 승인 계약 뒤에 둔다. 비유출·읽기/쓰기 범위·외부 관찰 부재·할당/Drop·종료·참조 동등성을 기록한다. Aeneas식 함수형 변환은 지원 코드의 검증 선택지이지 임의의 안전한 Rust가 이미 순수하다는 증명이 아니다.

**RS-008** 검사/포화/순환 산술을 명시하고 디버그/릴리스의 오버플로 차이에 의존하지 않는다. 재귀·반복자 작업·입력 크기·할당 요구에 한도를 둔다. `Result`는 할당기 abort·스택 오버플로·panic-abort를 복구 가능한 오류로 바꾸지 않는다. 복구 계약이 요구하고 지원하는 곳에 실패 가능한 할당 API를 사용하고 남은 프로세스 수준 가정을 기록한다.

**RS-009** 중첩/제네릭 값과 오류 시 버려지는 값을 포함해 효과 있는 `Drop`을 의미 값에서 배제한다. RAII는 정리를 돕지만 abort·누수·forget·외부 강제 종료까지 보장하지 않는다. 실패 가능한 마무리는 명시적 연산으로 만들고 최초 실패와 정리 실패를 함께 보존한다. unwind에 확실한 복구를 의존하지 않는다.

**RS-010** async는 소유자·동시성 한도·합류·취소 정책을 가진 효과 경계로 다룬다. future를 drop했다고 원격 쓰기가 롤백되거나 실행되지 않았다고 판단하지 않는다. 결과 불명과 작업 ID를 모델링하고 소유 자원에 관련된 각 중단점의 취소를 검사한다. 명시적 근거와 테스트 없이 분리된 작업이나 중단점을 가로지르는 잠금 보유를 허용하지 않는다.

**RS-011** FFI/unsafe는 안전 전제조건과 안전한 도메인 값 변환을 명시한 좁은 어댑터에 둔다. C 연동에는 두 프로파일을 적용한다. ABI 표현·null/길이·소유권/해제기 짝·수명·스레드/콜백·panic/unwind를 고정한다. Rust enum·slice·reference·할당기 소유 버퍼를 임의의 C 표현처럼 공개하지 않는다.

## 검증과 보장

**RS-012** edition·MSRV/도구체계·feature·타깃·panic 전략·의존성 버전을 기록한다. 포매터·컴파일러·프로젝트별 Clippy·테스트·관련 feature/타깃 조합을 실행한다. 디버그·릴리스 의미를 검증하며 `debug_assert!`를 배포 필수 불변식 검사로 사용하지 않는다. 통과만을 위해 광범위한 lint 허용이나 `unsafe`를 추가하지 않는다.

**RS-013** 도메인 생성기/축소기·참조 모델 비교·실패 주입·필요한 제어 스케줄 테스트를 사용한다. Miri·sanitizer는 지원 실행 범위의 동적 근거이며 Clippy·unsafe 금지는 순수성 증명이 아니다. 미지원 도구와 미해결 의무를 기록하고 통과로 표시하지 않는다.

**RS-014** 형식 검증에는 지원 부분집합·추출/도구 버전·백엔드 모델·의존성 계약·미증명 의무·종료 주장을 명시한다. Aeneas의 설명된 접근은 unsafe/내부 가변성 등 중요한 패턴을 제외하므로 FFI·임의 async 런타임까지 검증했다고 추론하지 않는다. 순수 모델에 대한 정제는 범위가 있는 근거이지 전체 시스템 정확성 인증이 아니다.
