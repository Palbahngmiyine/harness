# C 함수형 프로그래밍 프로파일

[영문 원본](c.md)이 기준이다. [공통 규칙](../AGENTS.md)·[검증](../fp/verification.md)과 함께 적용한다. 근거: [출처](../references/functional-programming.md).

범위: 이 문서는 서술형 정책이다. 아래 구현·실행 검증 의무는 실제 C 소프트웨어 또는 외부 언어 경계를 변경할 때 적용한다. 프로파일 문장만 수정할 때에는 CHK-014의 문서 검토를 사용한다. 예제 코드나 실행기는 본 패키지에 추가하지 않는다.

## 의미 모델과 표현

**C-001** 의미 코어는 명시적 성공/오류 태그를 가진 값 변환으로 작성한다. 작은 데이터는 값 구조체를, 표현에 민감한 데이터는 비공개 구현 타입을 우선한다. C의 `typedef`는 별도의 검증된 타입이 아니다. 모든 생성 경로를 숨기거나 검증한다. 태그/페이로드 유효성을 명시하고 신뢰하지 않는 태그는 페이로드 선택 전에 거부한다.

**C-002** `const T *`는 해당 뷰를 통한 접근을 제한할 뿐 깊은 불변성·독점 소유권·다른 별칭의 변경 부재를 증명하지 않는다. 포인터 범위·초기화·정렬·수명·변경 가능한 주체를 명시한다. 스냅샷 전에 데이터 경합 없는 접근을 확보한다. 동시에 변경되는 비원자 저장소를 복사하는 것은 안전하지 않다. 입력 경계에서 소유권 이전이나 동기화를 사용하고 여러 필드의 스냅샷 일관성을 명시한다. 필드별 atomic만으로 일관된 스냅샷이 되지는 않는다. 불안정한 빌린 상태를 순수 입력으로 인정하지 않는다.

**C-003** 순수 API는 새 값을 반환하고 호출자가 관찰하는 입력/출력 저장소를 변경하지 않는다. 일반적인 출력 버퍼 API는 쓰기 경계이지 순수 함수가 아니다. 큰 결과는 순수한 크기/계획 계산과 승인된 생성 커널을 분리하고 완성된 불변 결과만 공개한다. 용량 오류·겹침·실패 원자성·소유권 이전을 명시한다.

**C-004** 지역 카운터·임시 버퍼·제자리 알고리즘은 FP-007에 따라서만 허용하고 불변 참조 명세를 분리한다. 할당·사용자 할당기·해제·실패 콜백은 명시적인 계약이 필요하다. 포인터가 비공개라는 이유로 내부를 모르는 변경 함수를 순수하다고 하지 않는다. 주소 식별성·할당기 상태를 도메인 판단에서 배제하고 자원 실패 동작을 명시한다.

## 효과와 정의된 동작

**C-005** 코어 의존성에서 전역/스레드 지역 상태·`errno`·로케일·부동소수점 환경 변경·volatile/MMIO·시계·I/O·효과 콜백을 배제한다. 불변 표는 허용한다. 외부 입력은 어댑터에서 스냅샷으로 얻는다. 함수 포인터에 효과·수명 계약이 필요하며 콜백 인자는 효과 시스템이 아니다. GCC `pure`/`const` 속성은 최적화에 대한 약속이지 증명 도구나 이식 가능한 순수 타입이 아니다.

**C-006** 실제 C 버전·컴파일러 옵션·타깃 폭·확장 정책을 기록한다. 동등식 추론 전에 부호 있는 오버플로·잘못된 시프트/나눗셈·범위 밖 포인터 산술·해제 후 사용·미초기화 읽기·정렬 오류·유효 타입 위반 등 미정의 동작을 차단한다. 순환/포화/검사 산술을 의도적으로 정의한다. unsigned 순환 자체는 도메인 명세가 아니다.

**C-007** `restrict`는 의무가 있는 별칭 계약이며 소유권 검사기가 아니다. 메모리 분리 전제를 명시하고 신뢰할 수 있는 호출부에서 보장한다. 함수형처럼 보이게 하려고 추가하지 않는다. 이식 가능한 C는 숫자 주소만으로 임의 포인터의 수명이나 범위를 검증하지 못한다. 잘못된 바이트 입력은 유효성이 확보된 메모리 영역 안에서 안전하게 거부한다.

**C-008** 임의 구조체 바이트·패딩 대신 의미 있는 필드를 비교·직렬화한다. 엔디언·정수 범위·태그 인코딩·문자열/바이트 길이를 명시한다. 외부 바이트를 구조체로 캐스팅하거나 C enum을 검증된 Rust enum처럼 전달하지 않는다. 관련된 경우 NaN·부호 있는 0·로케일·부동소수점 평가 옵션을 도메인 계약으로 다룬다.

**C-009** 예상 실패는 태그와 오류 페이로드로 표현하고 공개 출력은 태그 계약에 맞춰 초기화한다. 배포 검증이 `NDEBUG`에서 사라지면 안 된다. 필수 런타임 검사에 `assert`만 사용하는 것은 불충분하다. 도달 불가 내부 분기는 결함을 드러내되 미정의 동작을 오류 처리기로 사용하지 않는다.

## 자원과 검증

**C-010** 할당·파일·잠금·프로세스마다 어댑터에 소유자와 정리 경로를 명시한다. 부분 획득·정리 실패를 정의한다. 별도로 검증된 정리 설계 없이 소유 자원을 가로지르는 `longjmp`나 비동기 중단을 사용하지 않는다. 해당하는 할당/I/O의 첫·N번째·매 호출 실패를 주입한다.

**C-011** include/호출 의존성 검사에 경고·정적 분석을 결합한다. 단순 심벌 검색은 매크로·간접 호출·인라인·동적 링크를 완전히 다루지 못한다. 값 함수의 허용 사례와 `const` 별칭 변경·전역 읽기 같은 적법한 반례를 함께 확인한다. 반례의 컴파일 성공은 언어가 순수성을 강제하지 않는다는 예상된 증거다.

**C-012** 프로젝트가 지원하면 ACSL/Frama-C로 전제조건·결과 관계·읽기 의존성·쓰기 범위·분리·루프 불변식·감소 척도를 명세한다. `assigns \nothing`만으로 가변 전역 읽기나 비종료를 배제하지 못한다. 메모리 모델·호출 함수 가정·런타임 오류 의무·증명 완료 항목·미확정/시간 초과를 기록한다. 주석이나 일부 증명 완료를 프로그램 전체의 증명으로 취급하지 않는다.

**C-013** 디버그·최적화·실제 배포 빌드를 검사하며 필수 검사는 `NDEBUG`에서도 유지한다. 지원되는 주소/미정의/race/메모리/누수 분석을 호환되는 별도 빌드에서 실행하고 계측 범위와 런타임 한계를 기록한다. 승인 커널을 단순 순수 모델과 비교하고 유효한 별칭 배치·산술 경계·취소·복구를 검사한다. 일반 테스트에서 미정의 동작을 실행한 뒤 비충돌을 정확성으로 해석하지 않는다.

**C-014** C의 외부 언어 경계에서는 영향받는 프로파일을 모두 읽고 Rust 연동에는 Rust, cgo에는 Go 프로파일도 적용한다. 길이·null 허용·소유권/해제자 짝·별칭·수명·호출 규약·정렬·스레드/콜백·오류/unwind 정책을 명시한다. 외부 오류를 도메인 값으로 변환하고 가변 핸들을 의미 코어에 전달하지 않는다. 적용 소프트웨어를 변경하면 실제 언어 간 경계 테스트를 수행한다. 이 서술형 프로파일은 실행 근거가 아니다.
