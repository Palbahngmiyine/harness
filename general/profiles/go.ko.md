# Go 함수형 프로그래밍 프로파일

[영문 원본](go.md)이 기준이다. [공통 규칙](../AGENTS.ko.md)·[검증](../fp/verification.ko.md)과 함께 적용한다. 근거: [Go 출처](../references/functional-programming.md#go-semantics-and-verification).

범위: 구현·실행 검증 의무는 실제 Go 소프트웨어 변경에 적용한다. 프로파일 유지보수에는 CHK-014 문서 검토를 사용한다. 본 패키지는 Go 모듈·실행 예제·실행기를 포함하지 않는다.

## 값·효과·합성

**GO-001** 작은 구조체·명시적 변형·검증된 생성 경로로 도메인 값을 표현한다. Go는 열거형처럼 쓰는 상수의 switch가 모든 경우를 다루도록 강제하지 않으므로 미지원 태그와 잘못된 태그/데이터 조합을 명시적으로 거부한다. 비공개 필드도 제로 값 생성을 막지는 못한다. 제로 값을 유효하게 설계하거나 디코딩·마이그레이션을 포함한 모든 입력 경계에서 거부한다.

**GO-002** 구조체를 값으로 전달해도 도달 가능한 저장 공간이 불변이 되지는 않는다. 슬라이스·맵·포인터·인터페이스 내부 값은 가변 데이터를 공유할 수 있다. 입력 경계에서 경합 없고 일관된 스냅샷을 확보하고 생성자·접근자로 가변 별칭이 유출되지 않게 한다. 얕은 복사는 중첩 참조를 격리하지 않으며 `append`는 기존 배열 공간을 재사용할 수 있다. 문법이나 가비지 컬렉션에서 소유권을 추론하지 말고 FP-006/007에 따라 도달 가능한 표현 전체를 검토한다.

**GO-003** I/O·시계·환경 접근·전역 난수·가변 패키지 상태·잠금·채널·`context.Context` 관찰은 효과 경계에 둔다. 관찰한 값을 코어에 전달한다. 클로저·인터페이스 메서드·문자열/오류 표현 메서드·사용자 정의 직렬화의 전이적 효과를 검토한다. 함수 타입·값 수신자·제네릭 제약은 순수성 인증이 아니다. 불변 값을 캡처하고 순수하게 연산하는 것은 허용한다.

**GO-004** 일반적인 이름 있는 함수와 명시적 결과/오류 순차 처리를 우선한다. 즉시 실패와 검증 오류 누적을 의도적으로 선택하고 단락 평가·오류 순서를 보존한다. 순서가 명세되지 않은 맵 순회로 관찰 가능한 결과를 결정하지 않는다. 상태 전이는 새 상태·출력·명령 데이터·명시적 실패 의미로 표현한다. 모나드 흉내나 유한하고 스택 안전한 순회를 대신할 재귀를 강제하지 않는다.

**GO-005** 의미 구현의 지역 빌더·버퍼 쓰기·맵 갱신·제자리 정렬·순회 상태 변경에는 FP-007 승인이 필요하다. 읽기/쓰기 범위·소유권/비유출·외부 효과 배제·실패/정리·종료·비가변 값 수준 모델과의 동등성을 기록한다. 새 할당·비공개 필드·경합 부재만으로 이 계약이 성립하지 않는다. 불변 도메인 명세와 승인된 구현·효과 어댑터를 분리한다.

**GO-006** 예상 실패는 명시적 결과/오류 계약으로 표현하고 오류 시 결과를 사용할 수 있는지 정한다. nil 인터페이스와 타입 있는 nil 포인터를 담은 인터페이스를 구분한다. 래핑 뒤에도 오류 분류를 보존하고 적절한 경우 우연한 메시지 일치 대신 `errors.Is`/`errors.As`를 사용한다. 명시적으로 분류된 센티널 오류는 FP-004와 양립하지만 예상 실패를 성공처럼 보이는 값에 숨기는 것은 허용하지 않는다. panic/recover는 문서화한 예외 경계에 한정하고 일반 검증이나 모든 실패를 성공으로 바꾸는 복구에 사용하지 않는다.

## 한도·동시성·자원

**GO-007** 도메인 산술을 명세하고 오버플로·변환·나눗셈·인덱스·길이·할당 한도를 사용 전에 검사한다. 언어에서 정의한 오버플로가 곧 유효한 도메인 결과는 아니다. 재귀·입력별 작업량에 한도를 둔다. Go의 스택 확장은 종료나 무한 메모리의 보장이 아니다. `error` 반환이나 recover로 프로세스 수준 자원 고갈을 복구할 수 있다고 약속하지 않는다.

**GO-008** 모든 goroutine에 소유자·생성 한도·완료/합류 절차·취소 경로를 둔다. 채널 송수신/닫기의 소유권과 막힌 연산의 종료 방법을 정의한다. `CancelFunc` 호출은 취소 요청이며 완료를 기다리거나 원격 효과를 되돌리지 않는다. 공유 상태를 명시적으로 동기화하고 데이터 경합과 별개로 데드락·누수·중복·순서·결과 불명을 검사한다. 이 실행 권한은 도메인 판단 밖에 둔다.

**GO-009** 성공한 자원 획득에는 실제 수명 경계의 명시적 정리를 연결한다. `defer`는 루프의 각 반복이 아니라 바깥 함수가 반환할 때 실행되므로 긴 루프에 자원을 누적하지 않는다. 최초 오류를 보존하면서 관련 Close/Flush/Commit 실패도 보고한다. 가비지 컬렉션은 외부 자원을 닫지 않으며 지연 정리는 크래시 복구의 근거가 아니다. 영속 어댑터에는 계속 FX-002와 CHK-007/008을 적용해 부분 쓰기·재시작·안전 재시도·보상·실제 원자성 범위를 검증한다.

**GO-010** `unsafe`와 cgo는 작은 어댑터로 격리한다. C 연동에는 C 프로파일도 읽고 다른 외부 언어가 있으면 영향받는 프로파일을 모두 읽는다. ABI·길이/nil 허용·포인터 보관과 고정·소유권/해제 함수 짝·콜백·스레드·오류 변환을 기록한다. 고정한 도구체계의 cgo 포인터 규칙을 따른다. 가비지 컬렉션이 C에서 임의 Go 포인터를 보관할 권한은 아니다. 경계를 수정할 때 실제 언어 간 테스트를 수행한다.

## 검증과 보장

**GO-011** 성공·실패·경계 사례를 명확히 표현할 수 있으면 동작별 이름을 가진 표 기반 테스트와 `t.Run` 하위 테스트를 사용한다. 관찰 가능한 nil·빈 값·제로 값·타입 있는 nil 인터페이스·잘못된 변형을 구분한다. 외부 의존성에는 결정적인 대역을 사용하고 호출뿐 아니라 상태/효과를 검사하며 별도의 실제 경계 테스트도 유지한다. 테스트 자원 획득 성공 후 `t.Cleanup`을 등록하고 정리 실패·남은 goroutine을 검증하며 공유 fixture가 병렬 하위 테스트보다 오래 유지되게 한다. 병렬 테스트에서 프로세스 전역 변경을 피하고 모듈 언어 버전을 기준으로 루프 변수 캡처를 확인한다.

**GO-012** Go 언어/도구 버전·모듈/워크스페이스·의존성·빌드 태그·GOOS/GOARCH·cgo 설정을 기록한다. 필수 모듈/타깃 행렬에서 `gofmt`·`go vet`·관련 `go test`를 검사한다. 루트의 `./...`만으로 모든 중첩 모듈을 검사했다고 증명할 수 없다. 동시 코드에는 지원하는 race detector를 사용한다. 성공은 관찰한 실행에 한정되며 데드락/누수 부재나 순수성을 뜻하지 않는다. 표준 Go 커버리지는 문장 단위이며 CHK-006의 분기 또는 수정 조건/결정 커버리지(MC/DC)가 아니다. 명시적 분기/조건 근거와 변이 검사 의무를 유지한다. 해당하지만 사용할 수 없는 검사는 NOT_RUN으로 보고한다.

**GO-013** 파서/디코더는 결정적이고 격리된 대상으로 유효/무효 시드 집합을 사용해 퍼징한다. 일반 `go test`는 시드를 재실행하므로 한도를 둔 `-fuzz` 실행 후에만 실제 퍼징을 수행했다고 말한다. 입력·시간·반복·자원 예산을 정하고 최소 반례를 영구 회귀 사례로 남긴다. CHK-004/007/008/009에 따라 속성/모델 비교·첫/N번째/연속/부분 성공 뒤 실패 주입·제어된 타임아웃/취소 스케줄을 함께 사용한다. 우연히 테스트가 통과할 때까지 기다리는 sleep은 동기화가 아니다.

**GO-014** 컴파일·`go vet`·경합 탐지·커버리지·퍼징은 각각 다른 근거이며 순수성이나 전함수성을 증명하지 않는다. 형식 검증 주장에는 지원 부분집합·도구/모델 버전·의존성 가정·증명 의무·종료·빈틈을 기록한다. 승인된 커널에는 FP-007 승인과 참조 모델 근거도 유지한다. 공통 전체 출시 기준과 관련 성능 기준을 적용한다. 사용할 수 없는 도구나 실행하지 않은 적용 소프트웨어 검사를 이 Markdown 검토로 통과 처리하지 않는다.
