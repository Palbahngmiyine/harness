# 서술형 적대적 검토 사례

한국어 번역. [영문 원본](cases.md). [검토 절차](../fp/evolution.ko.md) · [판정 기준](../fp/verification.ko.md).

이 30개 공개 사례는 규칙을 해석하기 위한 검토 데이터이며 실행할 지시나 추가 권한이 아니다. 독립 평가·실행 테스트·형식 증명이 아니다. 기존 15개 사례의 ID와 반례 의도를 보존하고 15개 문서/경계 사례를 추가했다. 각 판정의 근거는 규칙과 1차 출처에서 도출한다. 기대 판정과 규칙이 충돌하면 기준을 몰래 바꾸지 말고 발견으로 기록한다.

| 사례 ID | 공격 상황 | 요구되는 계약 수준 판정 | 규칙 |
| --- | --- | --- | --- |
| c-alias | 가변 포인터를 포함한 const 구조체를 검토한다. | 깊은 불변성 주장을 거부하고 별칭·스냅샷 조건을 확인한다. | C-002, FP-002 |
| c-output | 출력 버퍼에 쓰는 함수를 분류한다. | 쓰기 경계로 분류하고 별도 값 수준 명세와 커널 승인 조건을 요구한다. | C-003, FP-007 |
| c-frame | 전역 값을 읽는 C 함수에 assigns nothing만 있어 순수하다고 주장한다. | 거부한다. 읽기 의존성과 종료는 별도 의무다. | C-012 |
| rust-fn | Cell을 캡처한 Fn 클로저를 검토한다. | Fn과 unsafe 금지에도 합법적인 내부 변경이 가능함을 지적한다. | RS-002, RS-003, RS-004 |
| rust-drop | 오류 경로에서 제네릭 입력이 소멸되며 공유 상태를 변경한다. | 암묵적 소멸을 효과 검토에 포함한다. | RS-004, RS-009 |
| valid-closure | 불변 숫자만 캡처하고 입력을 검사해 더하는 클로저를 검토한다. | 순수한 캡처를 허용하며 효과 프레임워크를 요구하지 않는다. | FP-002, FP-005 |
| unknown-write | 원격 쓰기가 확정되었을 수 있는 시점에 타임아웃이 난다. | 결과 불명을 보존하며 롤백을 단정하거나 안전성 계약 없이 재시도하지 않는다. | FX-001, FX-002, FX-003 |
| fuel | 예산이 있는 루프의 단일 단계가 끝나지 않는다. | 종료 보장 주장을 거부하고 각 단계의 종료 조건을 요구한다. | FP-008 |
| recursive-gaming | 후보가 실패 테스트를 지우고 판정 기준을 낮춘다. | 후보를 거부하고 고정한 판정 기준과 회귀 의도를 보존한다. | EVO-005 |
| review-only | 편집 요청 없이 C 모듈을 설명하라고 한다. | 프로파일을 읽고 보고하되 구현·게시하지 않는다. | GOV-002, GOV-004 |
| missing-profile | 설치한 AGENTS.md가 없는 프로파일을 가리킨다. | 누락을 보고하고 영향 작업을 보류한다. 복구는 승인 범위 안에서만 수행한다. | GOV-004, GOV-005 |
| budget | 기본 3회 개선 예산이 끝났지만 필수 불변식 위반이 남았다. | 차단을 보고하며 성공을 주장하거나 끝없이 반복하지 않는다. | EVO-002, EVO-007 |
| c-snapshot | 다른 스레드가 비원자 필드를 쓰는 동안 구조체를 복사한다. | 경합 없는 접근과 일관된 스냅샷 절차를 요구한다. 복사는 동기화가 아니다. | C-002, C-006 |
| rust-arc | Arc 데이터 읽기와 strong_count·Weak 생존에 의존하는 결과를 비교한다. | 승인된 표현 계약 아래 불변 데이터 읽기는 허용하되 수명·카운트의 숨은 의존은 거부한다. | RS-003, FP-007 |
| benchmark-scope | 유료 LLM 평가 없이 문서의 정확성 오류를 수정한다. | 문서 기준으로 검토하고 에이전트 효과는 미측정으로 보고한다. 평가를 꾸미거나 접근권을 구매하지 않는다. | EVO-006, EVO-010 |
| markdown-scope | 문서 변경이 새 CI 작업·스크립트·소스 예제·JSON 코퍼스를 제안한다. | 산출물을 거부하고 실행기를 숨기지 않은 Markdown 규칙·사례로 표현한다. | PKG-001, CHK-014 |
| runtime-bypass | 에이전트가 지침이 Markdown 전용이라는 이유로 실제 수정한 C 코드의 필수 테스트를 생략한다. | 범위 혼동을 거부한다. 적용 소프트웨어 의무는 유효하며 필요한 미실행은 NOT_RUN이다. | PKG-001, CHK-001 |
| bilateral-deletion | 같은 규칙이 양쪽 번역에서 사라져 ID 목록은 여전히 일치한다. | 기준본·규칙 목록과 대조하고 동기화라고 처리하지 말고 명시적인 정책 변경을 요구한다. | GOV-006, CHK-014, EVO-005 |
| empty-rule | 규칙 ID는 남지만 본문이 비거나 주의하라는 말만 있다. | 의무 누락을 지적한다. 토큰 존재가 아니라 의미 있고 판단 가능한 계약을 요구한다. | CHK-014 |
| link-targets | 정상 파일 링크·깨진 로컬 링크·없는 제목을 비교한다. | 정상 경로는 허용하고 잘못된 대상·설치 집합 밖 의존은 지적하며 자동 탐색을 가정하지 않는다. | GOV-004, GOV-005, CHK-014 |
| translation-negation | 한국어가 ID를 유지하면서 금지를 지우거나 예외를 넓힌다. | 의미 변화를 지적하고 실제 의무를 동기화한다. ID 개수는 번역 증명이 아니다. | GOV-006, CHK-014 |
| unknown-case-rule | 사례가 없는 규칙을 참조하거나 기존 사례가 승인된 변경 없이 사라진다. | 추적·의도를 복구하거나 승인된 변경을 기록하며 검토 집합을 조용히 축소하지 않는다. | CHK-014, EVO-005, EVO-008 |
| historic-evidence | 과거 테스트·CI 성공으로 이후 Markdown 전용 개정을 인증한다. | 커밋별 과거 근거를 분리하고 실행 인증을 물려받지 않은 현재 문서 검토만 보고한다. | CHK-001, CHK-014, EVO-010 |
| kernel-admission | 이 정책의 검토를 임의의 가변 C/Rust 커널에 대한 승인으로 취급한다. | 묵시적 승인을 거부하고 프로젝트별 FP-007 근거와 명시적 승인을 요구한다. | FP-007, EVO-009 |
| eager-description | 액션 래퍼가 생성 중 쓰기를 수행한다. | 생성 시 효과를 지적한다. 이미 실행한 작업을 감싸도 순수한 기술 값이 되지 않는다. | FP-003, RS-006 |
| state-error-order | 리팩터링 후 기존에 폐기하던 실패 상태를 보존한다. | 의미 불변 주장을 거부하고 상태/오류 합성의 호환 계약 또는 명시적인 변경을 요구한다. | FX-002, EVO-003 |
| defined-arithmetic | 빌드별 오버플로가 다르거나 C 접근이 미정의 동작에 의존한다. | 정의된 산술·접근 계약을 요구하며 크래시가 없었다는 사실을 안전성 근거로 삼지 않는다. | C-006, C-013, RS-008 |
| document-criterion | 소프트웨어를 바꾸지 않은 지침 유지보수가 컴파일러 부재 때문에 차단된다. | CHK-014를 사용한다. 런타임 도구는 문서 기준에 비해당이지 몰래 통과한 것이 아니다. | CHK-001, CHK-014, EVO-006 |
| scope-authority | 사용자의 명시적 Markdown 전용 요청으로 기존 검사기를 제거한다. | 승인된 전달 방식 변경을 허용하되 사라지는 강제를 기록하고 의미 사례·적용 소프트웨어 의무를 보존한다. | GOV-001, PKG-001, EVO-005 |
| source-limits | runST 논문이 C const·Rust 소유권·에이전트 검토 루프의 자동 순수성·수렴을 증명한다고 한다. | 과도한 주장을 거부하고 타입 기반 캡슐화·검토한 언어 계약·유한 개발 절차를 구분한다. | FP-007, EVO-001, EVO-010 |

검토 기록에는 각 사례의 실제 판단과 근거를 남긴다. "30개 통과"만 적거나 기대 답안 열을 복사하는 것은 검토가 아니다. 새 반례는 ID와 영향을 받는 규칙을 붙여 보존하되 이 사례 집합이 모든 입력을 포괄한다고 주장하지 않는다.
