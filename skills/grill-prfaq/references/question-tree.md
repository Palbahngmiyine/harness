# 질문 트리

트리의 뿌리는 Working Backwards의 다섯 질문이다. Q0가 고객 유형을 정하고, 유형이 F1~F5의 문구를
정한다. 가지는 답이 가설 슬롯을 바꾸거나 FAQ 항목을 만들 때만 뻗는다.

## 1. Q0 — 고객 유형

라운드 1의 첫 질문이다. 아이디어를 읽고 추천을 단다.

```
❓ **Q1** - **고객 유형**: 이 아이디어로 덕을 보는 쪽은 누구입니까? A 외부(돈이나 시간을 내는 사람) / B 내부(개발자·운영자) / C 없음(고장·부채·정리)

➡️ <A/B/C 중 하나와 한 문장 이유>
```

답이 C면 frontmatter를 `customer: none`으로 두고 §3에 `- 「해당 없음」 — Q0, R1`을 쓴다.
「해당 없음」은 settled가 아니라 범위 밖이다. F1~F5는 failure-root 문구를 쓴다.

아이디어가 제품 둘 이상이나 독립된 결정 둘 이상을 담고 있으면 Q0 대신 §5의 분할 질문을 먼저 낸다.

## 2. 뿌리 다섯 — 유형별 문구

| 슬롯 | external | internal | failure-root (none) |
|---|---|---|---|
| F1 | 고객: 누가 쓰고, 누구는 아닌가 | 고객: 어느 팀·역할이 쓰고, 누구는 아닌가 | 대가: 지금 누가 비용을 치르나 |
| F2 | 문제: 지금 어떻게 우회하고, 얼마나 자주 겪나 | 문제: 지금 어떻게 우회하고, 얼마나 자주 겪나 | 깨지는 것: 지금 무엇이 어떻게 깨지나 |
| F3 | 핵심 이익: 하나만 고르면 무엇인가 | 핵심 이익: 하나만 고르면 무엇인가 | 가능해지는 것: 고치면 무엇이 가능해지나 |
| F4 | 근거: 그들이 원한다는 것을 어떻게 아나 | 근거: 그들이 원한다는 것을 어떻게 아나 | 근거: 깨진다는 것을 어떻게 아나 |
| F5 | 경험: 첫 접점은 무엇이고 실패하면 무엇이 보이나 | 경험: 첫 접점은 무엇이고 실패하면 무엇이 보이나 | 경험: 고친 뒤 첫 접점과 실패 시 보이는 것 |

§1 항목의 제목(`### F1. …`)은 이 표의 짧은 이름(고객 / 문제 / 핵심 이익 / 근거 / 경험, 또는 대가 /
깨지는 것 / 가능해지는 것 / 근거 / 경험)을 쓴다. §4 게이트 표의 차원명도 같은 이름이다.

## 3. 라운드 구성

- **R1** = Q0 + F2 + F4. F2와 F4는 고객 유형과 무관하므로 Q0와 같은 라운드에 묻는다. **F4에는
  선택지를 두지 않는다.** 본문은 "무엇을 보고 그렇게 아십니까?" 같은 열린 질문 한 문장이고,
  화살표 줄은 `➡️ 추천 없음 — 근거 또는 가정으로만`이다. 글자 하나짜리 답은 `가정`으로 적는다.
- **R2** = F1 + F3 + F5 + R1 답에서 뻗은 자식.
- **R3** = 자식. 보통 여기서 프론티어가 빈다.
- **R4** = 닫기 감사(`gate.md`).

## 4. 전형적인 자식

뿌리마다 자주 뻗는 가지다. 답이 이미 들어 있으면 묻지 않는다.

| 뿌리 | 자식 |
|---|---|
| F1 고객 | 세그먼트 경계는 어디인가 · 비고객은 누구인가 |
| F2 문제 | 지금 우회 방법은 무엇인가 · 빈도와 마지막 발생 시점 |
| F3 핵심 이익 | 무엇으로 측정하나 · 이 이익을 위해 무엇을 포기하나 |
| F4 근거 | 출처는 무엇인가 · 반례는 없나 |
| F5 경험 | 첫 접점은 어디인가 · 실패하면 사용자에게 무엇이 보이나 |

## 5. 자격 필터와 분할

질문은 답이 다음 셋 중 하나를 일으킬 때만 낸다.

1. §1 가설 슬롯 하나를 바꾼다.
2. §2 FAQ 항목을 추가하거나 고친다.
3. 항목을 §3 범위 밖으로 옮긴다.

셋 다 아니면 묻지 않는다. 사실은 묻지 않는다. 코드·문서·로그로 확인할 수 있는 것은 조사해
`**사실**`로 적는다.

프론티어가 8개를 넘으면 질문을 미루지 않고 분할 질문 하나만 낸다.

```
❓ **Q1** - **범위 분할**: 열린 결정이 <n>개입니다. A <가지 A> / B <가지 B> 중 지금 다룰 쪽은?

➡️ <하나와 한 문장 이유>
```

고르지 않은 가지는 §3에 `- <가지> — 다음 세션`으로 적는다.

## 6. 말로 답할 수 없는 질문

답이 "느낌", "모양", "배치", "흐름이 자연스러운가"에 걸리면 말로 풀지 않는다. 항목에
`**프로토타입 필요**`를 적고 §3에 올린 뒤 다시 묻지 않는다. 사용자가 프로토타입을 보고 돌아오면
그 답을 한 줄로 받는다.
