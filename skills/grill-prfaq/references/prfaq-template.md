# PR/FAQ 템플릿

라운드 1에서 아래 블록을 `docs/prfaq/<YYYY-MM-DD>-<slug>.md`로 그대로 복사한다. frontmatter는
여섯 키만 쓴다. `tags:`, `rounds:` 같은 키를 추가하지 않는다. 집계는 검증기가 센다.

`<…>`는 채울 자리다. 복사 뒤 `title`, `created`, `updated`만 채운다. Q0 답이 나오면 `customer`를
맞추고, C(none)이면 F1~F3 제목과 §4 표의 차원명을 `대가` / `깨지는 것` / `가능해지는 것`으로 바꾼다.
**§1 슬롯은 답이 오기 전까지 비워 둔다.** 산문으로 미리 채우지 않는다. 답이 오면 첫 줄에 태그 줄
하나를 넣는다. 형식은 아래 필드 규칙 표를 따른다.

```markdown
---
title: <아이디어 한 줄>
status: hypothesis
customer: external
created: YYYY-MM-DD
updated: YYYY-MM-DD
confirmed_at:
---

# <아이디어 한 줄>

**작성 규칙** — 확인된 사실만 산문으로 쓴다. 사용자만 쓸 수 있는 자리는 `【 】`로 비워 둔다. 사용자의 말은 「 」 안에 원문 그대로 적는다. status가 `prfaq`가 되기 전에는 §5가 비어 있다.

## 1. 가설

### F1. 고객

### F2. 문제

### F3. 핵심 이익

### F4. 근거

### F5. 경험

## 3. 범위 밖

## 4. 게이트

| 차원 | 등급 | 근거 |
|---|---|---|
| 고객 | | |

| 핵심 이익 | | |
| 근거 | | |
```

## 필드 규칙

| 자리 | 규칙 |
|---|---|
| `status` | `hypothesis` → `prfaq`. 진행하지 않기로 하면 `rejected`. 다른 값 없음 |
| `customer` | `external` / `internal` / `none`. `none`이면 §3에 `「해당 없음」` 줄이 있어야 한다 |
| `confirmed_at` | `status: prfaq`일 때만 채운다. 확인 문장의 날짜와 같아야 한다 |
| `**사실**` | `— 출처: <경로 또는 URL>, YYYY-MM-DD`를 같은 줄에 둔다 |
| `**결정**` | 사용자 말을 「 」 안에 원문 그대로. 요약·의역 금지. 끝에 `(R<n>)` |
| `**가정**` | `— 검증 계획: …` 또는 `**사용자 수용** 「원문」` 중 하나를 같은 줄에 둔다 |
| `**프로토타입 필요**` | 말로 답할 수 없는 항목. §1 슬롯이면 §3에도 `F<n> — **프로토타입 필요**` 줄을 올린다 |
| F4 | `**사실**`, `**결정**`, `**가정**`만 허용. 선택지를 두지 않고, `➡️`나 `추천` 문구를 넣지 않는다 |
| §1 슬롯 | 답 전에는 비워 둔다. `➡️` 추천을 어디에도 넣지 않는다 |
| §2 항목 | `### F6.`부터 번호를 이어 붙인다. `F4-1` 같은 하위 번호를 만들지 않는다 |
| §4 표 | 등급은 `poor / borderline / solid / outstanding`. 근거 칸에 실제 F-id. `outstanding`은 근거에 `**사실**` 항목이 있을 때만. `프로토타입 필요`와 사용자 수용 없는 `가정`은 `borderline`이 상한 |
| §5 | `prfaq` 전에는 placeholder 한 줄 그대로. 후에는 산문만, 불릿·번호 목록 없음 |
