# 한국어 맞춤법 검사 Skill

한국어 텍스트의 맞춤법, 띄어쓰기, 문법 오류를 검사하고 교정하는 skill입니다.

## 검사 절차

### 1단계: 입력 확인 및 파일 읽기

**인자가 없는 경우:**
인자 없이 `/korean-spell-check`만 호출된 경우, **AskUserQuestion 도구**를 사용하여 사용자에게 물어본다:

```
AskUserQuestion:
  question: "어떤 텍스트를 검사할까요?"
  header: "검사 대상"
  options:
    - label: "현재 열린 파일"
      description: "IDE에서 현재 열려 있는 파일을 검사합니다"
    - label: "파일 경로 입력"
      description: "검사할 파일의 경로를 직접 입력합니다"
    - label: "텍스트 직접 입력"
      description: "검사할 한국어 텍스트를 직접 입력합니다"
```

**파일 경로 감지 규칙:**
입력이 다음 조건 중 하나를 만족하면 파일 경로로 처리:
- 확장자가 있는 경우: `.md`, `.mdx`, `.txt`, `.html`, `.tsx`, `.ts`, `.js`, `.jsx`
- 경로 구분자 포함: `/` 또는 `\`
- 상대 경로로 시작: `./`, `../`, `src/`, `docs/`

**파일 처리 방법:**
1. 파일 경로로 판단되면 **반드시 Read 도구로 파일 내용을 읽는다**
2. 파일이 존재하지 않으면 오류 메시지 출력
3. 파일 내용 중 한국어 텍스트만 추출하여 검사 (코드 블록, frontmatter 제외 가능)

**텍스트 처리:**
- 인용부호로 감싸진 텍스트 → 직접 검사
- 파일 경로가 아닌 일반 텍스트 → 직접 검사

```
예시:
- "/korean-spell-check" → AskUserQuestion으로 검사 대상 확인
- "/korean-spell-check src/articles/2025/post.md" → Read 도구로 파일 읽기
- "/korean-spell-check ./README.md" → Read 도구로 파일 읽기
- "/korean-spell-check "안녕하세요"" → 직접 검사
```

### 2단계: 맞춤법 검사
다음 규칙에 따라 맞춤법 오류를 찾습니다:

| 항목 | 규칙 | 올바른 예 | 틀린 예 |
|------|------|----------|---------|
| 되/돼 | '되어'를 줄이면 '돼', 그 외는 '되' | 됐다, 되었다 | 됬다 |
| 웬/왠 | '웬' 단독 사용, '왠지'만 '왠' | 웬일, 왠지 | 왠일, 웬지 |
| 로써/로서 | 수단→로써, 자격→로서 | 펜으로써, 학생으로서 | 펜으로서 쓰다 |
| 데/대 | 장소/경우→데, 말하다→대 | 갈 데, ~라고 대답 | 할때 |
| 않/안 | 부정→않(아니하다), 안(아니) | 하지 않다, 안 하다 | 않하다 |
| 돼/되 | 해봐/해보아→돼, 해보→되 | 해 봐도 돼, 해 봐도 되어 | 해 봐도 되 |
| 며/면서 | 동시→며/면서 | 웃으며, 웃으면서 | 우스며 |
| 습니다/읍니다 | 현대어→습니다 | 합니다, 갑니다 | 합읍니다 |
| 세요/셔요 | '-시어요' 준말→세요 | 가세요, 하세요 | 가셔요 |
| 게/께 | 일반→게, 높임→께 | 어머니께 | 어머니게 |

### 3단계: 띄어쓰기 검사

| 규칙 | 설명 | 올바른 예 | 틀린 예 |
|------|------|----------|---------|
| 조사 붙여쓰기 | 조사는 앞말에 붙인다 | 학교에서, 친구와 | 학교 에서 |
| 의존명사 띄어쓰기 | 의존명사 앞은 띄운다 | 할 수 있다, 먹을 것 | 할수있다 |
| 보조용언 띄어쓰기 | 보조용언은 띄운다 | 해 보다, 먹어 버리다 | 해보다 |
| 단위명사 띄어쓰기 | 숫자 뒤 단위는 띄운다 | 한 개, 3 킬로미터 | 한개, 3킬로미터 |
| 고유명사 붙여쓰기 | 고유명사는 붙인다 | 대한민국, 서울특별시 | 대한 민국 |

**자주 틀리는 의존명사:**
- 수(능력), 것(대상), 데(장소), 바(사실), 리(이유), 줄(방법)
- 예: "할 수 있다", "먹을 것이다", "갈 데가 없다"

### 4단계: 문법 검사

| 항목 | 규칙 |
|------|------|
| 주어-서술어 호응 | 복수 주어→복수 서술어 |
| 조사 선택 | 받침 유무에 따른 은/는, 이/가, 을/를 |
| 시제 일치 | 문장 내 시제 통일 |
| 높임법 일관성 | 높임 표현 일관되게 사용 |
| 피동/사동 중복 | "잡혀지다" (X) → "잡히다" (O) |
| 이중 부정 | "없지 않다" 의미 명확히 |

### 5단계: 결과 출력

## 출력 형식

검사 완료 후 다음 형식으로 출력합니다:

### 파일 검사 시
```markdown
## 맞춤법 검사 결과

**검사 파일:** `src/articles/2025/example.md`

### 발견된 오류 (N개)

| 줄 | 원문 | 수정 | 규칙 |
|------|------|------|------|
| 15 | 됬다 | 됐다 | '되었다'의 준말은 '됐다' |
| 23 | 할수있다 | 할 수 있다 | 의존명사 '수'는 띄어쓰기 |

### 수정된 전체 텍스트

(교정된 텍스트 전문을 여기에 출력)

### 추가 개선 제안 (선택사항)

- 더 자연스러운 표현 제안
- 문체 개선 제안
```

### 텍스트 직접 검사 시
```markdown
## 맞춤법 검사 결과

### 발견된 오류 (N개)

| 위치 | 원문 | 수정 | 규칙 |
|------|------|------|------|
| 1문장 | 됬다 | 됐다 | '되었다'의 준말은 '됐다' |

### 수정된 전체 텍스트

(교정된 텍스트 전문)
```

### 오류가 없는 경우
```markdown
## 맞춤법 검사 결과

**검사 파일:** `src/articles/2025/example.md` (파일인 경우)

맞춤법, 띄어쓰기, 문법 오류가 발견되지 않았습니다.
```

## 사용 예시

### 인자 없이 호출 (대화형)
```
/korean-spell-check
```
→ AskUserQuestion으로 검사 대상을 물어봄 (현재 열린 파일 / 파일 경로 입력 / 텍스트 직접 입력)

### 텍스트 직접 검사
```
/korean-spell-check "나는 어제 학교에 갔었읍니다. 할수있는게 없어요."
```

### 파일 검사 (다양한 경로 형식)
```bash
# 상대 경로
/korean-spell-check src/articles/2025/my-post.md
/korean-spell-check ./README.md
/korean-spell-check ../docs/guide.md

# 절대 경로
/korean-spell-check /Users/user/project/article.md

# 현재 열린 파일 (IDE에서 열린 파일)
/korean-spell-check src/articles/2026/TEAM-AND-LEADERSHIP.md
```

### 마크다운 파일 검사 시 참고
- Frontmatter (YAML) 영역은 검사에서 제외해도 됨
- 코드 블록 내용은 검사에서 제외
- 한국어 본문만 집중 검사
