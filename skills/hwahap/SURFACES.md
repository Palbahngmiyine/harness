# Hwahap decision surfaces

각 applicable 표면에는 답변된 `decision`과 `scenario` choice가 하나 이상 필요하다.
해당 없음은 사용자가 `S<n>=NA`로 확정한다.

| ID | 결정 표면 | scenario 질문 예 |
|---|---|---|
| S1 | 목표, 성공·실패, non-goal, 우선순위, 범위 | 어느 관찰 결과가 실패인가? |
| S2 | 사용자 행동, 기본값, 순서, 원자성, 멱등성 | 같은 동작을 반복하면 무엇이 남는가? |
| S3 | 오류, 부분 실패, 복구, 롤백, 재시도 | 중간 실패 뒤 재시도하면 어디서 시작하는가? |
| S4 | 명령, 플래그, route, 이벤트, 설정, 타입, 경로, 포맷 | 잘못된 입력은 어떤 결과를 내는가? |
| S5 | 데이터·상태 소유, 수명, 영속, 삭제, 보존 | 프로세스 종료 뒤 무엇을 보존하는가? |
| S6 | API, 이벤트, 파일, 내부 계약, 스키마, 버전 | 구버전 소비자가 새 필드를 받으면 어떻게 되는가? |
| S7 | 아키텍처, 모듈 경계, 의존성, 기술 스택 | 한 의존성이 실패하면 어느 경계가 책임지는가? |
| S8 | 동시성, 타이밍, timeout, 순서, 자원 한도 | 두 작업이 겹치면 어느 순서로 완료되는가? |
| S9 | 호환성, migration, rollout, downgrade, 기존 사용자 | downgrade하면 새 상태를 어떻게 처리하는가? |
| S10 | 보안, privacy, 인가, 비밀, 파괴적 부작용 | 권한 없는 요청은 무엇도 바꾸지 않는가? |
| S11 | 성능 수치, 관측성, log, metric, trace, 운영 | 한도를 넘으면 어떤 신호와 대응이 필요한가? |
| S12 | 검증 setup, input, action, observable, pass, evidence | 어떤 명령 출력이 수용 증거인가? |
