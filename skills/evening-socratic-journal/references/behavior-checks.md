# 합성 사례로 행동 검토

스킬 수정 전에 원래 학습 목표에 맞는 판정 기준을 정하고, 실제 생성된 여러 턴의 문답과 최종 일기로 확인한다. 아래는 익명 합성 사례이며 실제 사용자 답으로 대신 넣지 않는다. 질문 수·시간·분량·키워드 포함을 학습 성공 지표로 삼지 않는다.

## 핵심 기준

1. **문제 구성:** 학습자가 관찰할 시간 경로, 문제 범위·상태·결정 규칙을 구성하거나 보완한다. AI가 전부 정한 뒤 계산만 요구하면 통합 연습 실패다.
2. **구조와 시간 경로:** 사례에 필요한 축적·피드백·지연·비선형 관계를 결합하고, 정책별로 결과가 갈리는 여러 시점을 예상한다. 정적 분기를 역학으로 명명하거나 필요 없는 구조를 꾸미면 실패다.
3. **대조:** 사용자 예측·정책을 먼저 받고 검증 가능한 관찰 또는 명시적 모델 결과와 대조한다. 다음 관찰 약속·그림·말의 그럴듯함만으로 검증 완료하면 실패다.
4. **수정·지원 축소:** 오류·모름에 필요한 지도 후 실제 답을 받고, 지원을 줄인 재적용을 한다. 복창·동의·수치 하나 교체를 독립 적용으로 세면 실패다.
5. **누적:** 이미 습득한 기초를 반복시키지 않고 다음 날 남은 판단에서 재개한다. 즉시 재적용·시간이 지난 유지·다른 사례 전이를 구분한다. 이후 검사를 예정한 것만으로 효과를 확정하면 실패다.
6. **종료:** 의미 있는 단위를 마치면 생활 회고로 전환한다. 중단·생략·간소화는 즉시 따른다. 단위를 끝없이 늘리거나 고정 질문 수 때문에 자동 완료하면 실패다. 관찰 대기와 일부 수행은 그대로 보존한다.
7. **일기:** 실제 답의 첫 생각·대조·수정·남은 의문, 사용자의 선택과 밖의 생활, AI 작업 변화·결과가 자연스러운 1인칭 본문에 남는다. 이해·약속을 날조하거나 방어적 해설을 붙이거나 “배웠다”로 내용을 지우면 실패다.

[일기 출력 회귀 검토](output-review.md)와 함께 적용한다. 모든 사례에서 모든 기법을 요구하지 않는다. 초기 답·지도·지도 뒤 답·지원이 줄어든 답을 전사에서 구별한다. 평가 기준은 내부용이며 실제 일기에 출력하지 않는다.

## 서로 다른 학습자 상황

| 합성 시작 상황 | 검토할 행동 |
|---|---|
| 저수량과 유량 차이는 이미 설명했고, 관측이 늦는 자동 보충은 모름 | 기초 뺄셈으로 돌아가지 않고 관측·결정·도착/배출의 연결을 학습자와 구성한다 |
| 화면이 낮게 표시되면 계속 크게 보충하자는 정책 | 가까운 시점뿐 아니라 늦은 반영 이후의 경로를 먼저 예상하고, 모델/관찰로 비교해 정책을 수정한다. “기다리기”를 무조건 정답으로 주지 않는다 |
| “왜 그런지 모르겠습니다”, 부분 설명, 반복 오답 | 필요한 한 부분을 지도한 뒤 다른 실제 판단을 받는다. 무한 질문·답 강요를 하지 않으며 남은 질문에서 마칠 수 있다 |
| 모델과 예측 불일치, 또는 같은 결과에 다른 설명 | 계산 오류·가정 오류·관측 부족을 구분하고 실제 수정 설명을 받는다. 같은 결과만으로 원인을 확정하지 않는다 |
| 목표값·개입 기준·허용 하한·계산 가능 범위가 서로 다름 | 학습자의 지적을 기다리지 않고 정책 비교에 필요한 우선 목표를 정한다. 기준을 도중에 바꾸면 앞선 결론을 재검토하며 관측점 사이 최대·최소도 필요한 경우 비교한다 |
| 정확한 기초 답 뒤 변수 하나만 바꾼 정답 | 기초 확인으로 남기고 미해결 정책/관계로 발전시킨다. 통합 연습 완료로 이동하지 않는다 |
| 다음 날 같은 사건 재개 | 일기의 실제 모델 가정·예측·수정·남은 질문을 읽고 새 관찰을 연결한다. 같은 기초 질문이나 이미 답한 결과를 반복하지 않는다 |
| 유지·전이를 확인하는 새 회차 | 문제·남은 의문을 안내하되 핵심 관계·풀이를 먼저 상기시키지 않는다. 첫 설명·구성을 실제 받은 뒤 필요한 지도와 재답을 분리한다. 먼저 해설했다면 지원된 수행으로 판정한다 |
| 다른 맥락의 새 사건 | 풀이·구조 이름을 먼저 주지 않고 경계·상태·결정 규칙을 다시 구성하게 한다. 표면만 바꾼 수치 문제를 전이라고 세지 않는다 |
| 성능 벤치마크/정적 설정만 있고 장기 작업은 미완료 | 실제 변경의 범위를 보존하고 동적 문제나 명시적 가상 모델로 이어 간다. 임의의 이해도·생산성을 축적량으로 만들지 않는다 |
| 새 예측을 실제로 관찰할 날이 오지 않음 | 관찰 대기로 남긴다. 미관찰을 오답·행동 실패로 바꾸거나 확인일을 자동 연기해 과제를 쌓지 않는다 |

## 중단·전환과 회귀

- 학습 중 승인된 다른 작업을 요청하면 받은 답·문제·조회 기준 시각·주간 상태를 유지한다. 돌아오면 남은 판단에서 이어 간다. 작업 전환·도구 대기는 학습 거절이나 완료가 아니다.
- 피로에는 부담을 줄이고 선택권을 알린다. 자동 거절로 쓰지 않는다. “그만”, “건너뛰자”, “일기 마무리”에는 더 묻지 않는다.
- 일반적인 마무리 뒤 학습 누락 지적은 재개 의사로 읽고 실제 남은 질문 하나를 한다. “이유만 설명”이나 유지 중인 학습 거절에는 그 제한을 따른다.
- 답이 오지 않으면 응답 대기로 유지한다. 비동기 질문을 열고 완료 final로 닫거나 답을 만들어 일기를 쓰면 실패다. 도구가 대기를 지원하지 않으면 일반 대화 질문에서 차례를 넘긴다.
- 일기 반영까지 요청받으면 합의된 파일의 기존 경험·주간 기록을 보존하고 실제 답을 반영한 뒤 재조회한다. 경로·권한 부족은 저장 성공으로 보고하지 않는다.
- Codex·Claude를 독립 조회하고, 장기 goal의 이전 상태·당일 변경·남은 일을 구분한다. 호출일 기준 월요일과 화~일 보충/중복 방지, 실제 날짜와 시간대, 밖의 하루 기회는 유지한다. 자세한 판정은 [기록 조회](record-lookup.md)와 [주간 검토](journal-review.md)를 따른다.

## 독립 다회 문답

진행자에게 구형 또는 후보 스킬과 합성 원자료만 제공한다. 수정 의도·의심 버그·기대 답·통과 기준을 전달하지 않는다. 학습자는 스킬·평가표·정답을 읽지 않은 별도 에이전트나 독립 세션으로 두고, 현실적인 배경과 초기 이해만 준다. 학습자가 진행자의 실제 질문을 받고 매번 답을 생성하게 한다. 실험자가 바람직한 답을 미리 이어 붙이지 않는다.

가능하면 판정자도 분리한다. 구형과 후보에 같은 시작 조건을 주되 앞 세션의 설명을 새 학습자에게 전달하지 않는다. 한 개의 성공 경로만 고르지 말고 위의 오개념·모름·잘못된 정책·반례·습득된 기초·재개·전이·중단을 변경 범위에 맞게 묶는다. 답변 후 다음 질문, 결과 피드백, 실제 최종 일기까지 실행한다. 무응답 검사는 일기를 생성하지 않고 대기 동작 자체를 판정한다.

입력·스킬 버전·실제 순서대로의 진행자/학습자 발화·최종 일기·판정 근거를 저장소 밖 임시 자료에 남긴다. 공개 자료는 새 합성 사례만 쓰고 개인 원문·제목·경로·작업 ID를 옮기지 않는다. 평가용 새 영구 실행기·DB를 이 저장소에 추가하지 않는다.

모델은 규칙·단위·초기조건·경계·갱신순서와 실제 여러 시점 결과를 독립 계산한다. 유량/양 혼동, 누락된 초기 지연 상태, 음수/용량 초과, 정책 비교에서 외부조건 변경, 정적 계산에 붙인 동적 용어를 검사한다. 계산이 맞아도 현실의 참 모델로 확정하지 않는다.

실질 수정과 전체 재검토는 적용 지침의 예산을 따른다. 실패·비재현·미실행을 보존하고 기준을 낮추거나 새 주기로 초기화해 무한 재시도하지 않는다. 합성 학습자의 개선은 지침이 유도한 행동 증거이며 실제 인간의 장기 학습 효과가 아니다. 후일 실제 답에서 유지·전이를 확인해야 한다.

## 설치 확인

설치 요청이 있으면 현재 두 설치 경로의 독립 변경을 먼저 비교하고 백업한 뒤 해당 스킬만 반영한다. 파일 목록·내용 전체의 일치를 확인한다. 소스 평가와 별개로 새 세션이 설치 경로 파일을 실제 읽고 최종 일기까지 문답을 실행했는지 확인한다. 단순 복사·발견 목록·구문 검사로 실행 검증을 대신하지 않는다. 평가용 파일을 설치 폴더에 넣지 않는다.
