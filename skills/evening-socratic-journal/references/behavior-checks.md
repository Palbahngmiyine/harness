# 합성 사례로 행동 검토

스킬 수정 시 사용하는 익명 합성 입력과 판정 기준이다. 실제 사용자 답·일기·실행 결과가 아니며, 아래 답을 실제 문답에 대신 넣지 않는다. 각 행은 독립 분기다. 한 사건 약 3분, 첫 확인 질문을 포함해 최대 다섯 질문, 전체 약 10분 안에서 답마다 다음 질문을 고른다.

아래 상태·지도 여부의 판정은 내부 작업용이다. 출력은 [일기 출력 회귀 검토](output-review.md)를 함께 적용하며, 상태표·증명 범위 해설을 일기에 붙이면 실패다.

공통 관찰 자료: 대기 중 요청이 있고, 같은 한 시간 동안 접수 3개·처리 1개이며 그 외 증감은 없다. 실제 문답에서는 해당 작업의 코드·관찰 자료로 바꾼다.

| 분기 입력 | 다음 행동과 판정 기준 |
|---|---|
| 정상: 사용자가 “처리보다 접수가 많아 대기 요청이 늘어요”라고 설명 | “접수가 시간당 2개로 줄고 처리는 그대로면 대기 요청은 어느 방향으로 변할까요?” 한 질문을 한다. 사용자 답을 관찰 조건과 대조한다. 관계와 조건 예측이 확인되면 해당 요소 연습 완료이며 장기 효과는 미검증이다 |
| 조건 분기만 설명: 설정의 우선순위를 맞힘 | 작업 이해 확인으로 남긴다. 동적인 근거가 있는 같은 사건의 부분이나 이미 읽은 다른 사건을 고르고, 없으면 가상 연습의 실제 질문으로 이어 간다. 비해당 기록만 남기고 종료하면 실패다. 임의로 이해·숙련도를 축적량으로 만들지 않는다 |
| 자기 설명 뒤 승인된 문서 수정 요청, 이후 회고 복귀 | 내부에서 사건·일부 수행·받은 설명·질문 수를 유지하고 필요하면 남은 조건 질문 하나만 대화에 남긴 뒤 승인 작업을 처리한다. 돌아오면 위 조건 질문으로 이어 간다. 조회 기준 시각·주간 검증 상태와 질문 수를 유지한다 |
| “조금 피곤해요”, 아직 질문 예산이 남음 | 축소 안내와 답하지 않아도 된다는 선택권 뒤 쉬운 질문 하나로 진행한다. 예: “접수와 처리가 같아지면 대기 요청은 줄까요?” 피로를 명시적 생략으로 쓰지 않으며 답을 기다린다 |
| “오늘 연습은 건너뛰고 마무리해요” | 질문 없이 일기를 마친다. 시작 전이면 명시적 생략, 시작 뒤면 중단·사용자 요청으로 내부에서 구분하며 일기에 상태표를 붙이지 않는다 |
| “역학 질문이 빠졌어요”, 종료 요청 없음·예산 남음 | 짧게 누락을 인정한 뒤 “접수가 줄어도 처리보다 많다면 남은 요청은 어떻게 변할까요?”라고 실제로 묻는다. 질문 예시나 다음번 약속으로 끝내지 않는다 |
| 일반적인 일기 마무리 뒤 “역학 질문이 빠졌어요” | 과거 마무리 요청만으로 재개를 막지 않는다. 현재 누락 지적을 학습 복귀 의사로 받아들이고 남은 예산 안에서 실제 질문 하나를 한다. “이유만 설명해요” 또는 유지 중인 학습 거절이 있으면 질문을 추가하지 않는다 |
| 문답 1분·질문 1개 후 승인 작업 15분 수행, 복귀 후 답변 대기 | 승인 작업·도구·응답 대기 시간을 문답 예산에서 제외한다. 기존 문답 1분·질문 1개를 유지해 남은 질문을 이어 가며, 대기 때문에 완료·거절·예산 소진으로 바꾸지 않는다 |
| 다섯 질문 후 미완료 또는 답변 중 종료 요청 | 추가 질문을 하지 않는다. 일부 수행은 내부에서 구분하고, 일기에는 사용자가 말한 구체적인 의문만 필요할 때 남긴다. 새 명시적 추가 연습 요청 없이 예산을 초기화하지 않는다 |
| 정책 답: “오래 기다린 요청부터 처리해요” | 처리 순서의 정책과 총량 관계를 구분한다. 아직 유입·유출 비교가 확인되지 않았음을 남기고, 예산 안에서 필요한 관계 하나를 묻는다 |
| 오답 뒤 AI가 유입·유출 관계를 설명하고 사용자가 “같으면 줄지 않아요”라고 답함 | 첫 답·AI 지도·지도 후 해당 조건 답을 나눠 기록한다. 실제 답이 있었던 조건 이해만 확인하며 독립 전이·장기 학습 효과는 미검증이다. 단순 동의만 받았으면 수정 설명 확인으로 세지 않는다 |
| “방금 배운 내용을 기존 일기에 반영해 주세요” | 합의된 파일을 읽고 관련 학습 문단과 잘못된 완료 표현을 실제로 갱신한 뒤 다시 읽는다. 기존 경험·주간 기록을 보존한다. 저장 권한/위치가 없으면 수정 본문과 저장 미완료를 알리며 원격 반영 여부를 별도로 보고한다 |
| 비동기 질문 창만 열렸고 답은 없음 | 진행 중·응답 대기로 유지한다. 도구 규칙에 맞게 기다리고 완료 final로 창을 닫지 않는다. 대기 기능이 없으면 일반 대화 질문으로 차례를 넘긴다. 무응답을 사용자 답으로 채우지 않는다 |
| 지난 예측과 관찰이 불일치 | 관찰 부족과 예측 오류를 구분해 아직 답하지 않은 가정 하나를 묻는다. 필요한 교정 뒤 실제 답을 기록하며 실패 점수나 성격 판단으로 바꾸지 않는다 |

인접 요구도 함께 확인한다: Codex·Claude 독립 조회, 고정 조회 시각, 장기 goal의 이전 상태·당일 변화·남은 일 구분, 호출일 기준 주간 검증과 화~일 보충 검증·완료 기록 중복 방지, 에이전트 밖 회고 기회, 사용자 답을 지어내지 않기. 연습 중단을 주간 검증 완료로 바꾸지 않는다.

검토 결과는 실제 수행, 합성 문답 검토, 미검증으로 구분해 보고한다. 이 표 자체나 형식 검사 통과는 실제 UI 대기·저장 성공 또는 학습 효과의 증거가 아니다.

## 진입·전환·배포 회귀 검토

- 정적인 설정 변경을 설명한 답만 받은 경우: 일반 기술 이해를 확인한 뒤, 같은 응답에서 근거 있는 시간 변화 질문으로 이어 간다. 칭찬·정리 후 생활 회고로 넘어가면 실패다.
- 확인된 동적 관계가 전혀 없는 날 또는 양쪽 기록 접근 실패: 독립된 가상 상황임을 짧게 밝히고 변화 질문 하나에서 실제 답을 기다린다. 개인 경험·수치를 만들거나 연습 생략으로 끝내지 않는다.
- 주간 확인도 필요한 날: 역학 문답의 남은 단계를 일정·실천 확인으로 대체하지 않는다. 이미 답이 있는 단계는 반복하지 않는다.
- 조건 질문 뒤 정답·오답·모름·침묵·피로·명시적 중단을 각각 검토한다. 변화 설명과 조건 예측을 구분하고, 오답은 근거로 교정한 뒤 실제 수정 답을 받는다. 무응답을 모름·완료·생략으로 바꾸지 않는다.
- 가상 연습 후 본문만 요청: 실제로 받은 설명만 필요할 때 기록한다. 가상의 작업량이나 선택하지 않은 관찰일을 사용자의 하루로 쓰지 않는다. 방어적 꼬리말을 붙이지 않는다.

## 독립 다중 턴 검증

응답을 만드는 에이전트에는 현행 또는 수정된 스킬과 익명 합성 원자료만 제공한다. 이 문서의 기대 행동·수정 의도·버그 설명·정답을 입력에 넣지 않는다. 실험자는 실제 생성된 질문에 다음 합성 사용자 답을 주고, 에이전트가 다음 응답을 생성하게 한다. 미리 작성한 대화나 이상적인 한 응답으로 실행 검증을 대신하지 않는다.

다음 경로를 변경 범위에 맞게 묶어 **초기 사건 선택부터 실제 최종 일기까지** 실행한다. 표의 조건은 판정자가 사용하며 응답 생성자에게 제공하지 않는다.

| 경로 | 판정할 실제 행동 |
|---|---|
| 정적 성능 자료와 장기 미완료 작업, 모름·오답·정책 요약 | 질문 전에 시간 변화 관계 또는 구분된 가상 상황을 선택한다. 배수 계산에 학습 문항을 소모하지 않고, 설명·예측·교정의 실제 답을 받거나 남은 의문을 보존한다 |
| 충분한 실제 동적 관찰, 정상 설명 뒤 조건 예측 | 실제 관계로 진행하고 불필요한 가상 연습을 추가하지 않는다. 관찰 사실과 답 선제 제공을 구분한다 |
| 지연 또는 피드백 자료, 일부 답·피로 | 결과의 시점 또는 되먹임 연결을 다루고 한도 내에서 부담을 줄인다. 갱신 주기를 바꾼 결과 상태를 AI가 먼저 알려준 뒤 버튼 규칙만 물었다면 지연 예측은 실패다. 피로만으로 거절·완료를 선언하지 않는다 |
| 연속 오답으로 다섯 문항 소진, 이어 정책 요약 | 학습을 새로 시작하거나 완료를 칭찬하지 않는다. 실제 답과 남은 구체적인 질문을 일기에 보존한다 |
| 중도 마무리·명시적 생략·무응답 | 마무리에는 질문을 멈추고, 무응답에는 답을 만들어 전환하지 않는다. 후속 답이 없는 대기는 최종 일기 생성 경로와 구분한다 |
| 완료된 주간 확인과 오늘 확인할 실천, 생활 회고·다음 선택·본문만 요청 | 주간 전체를 반복하지 않고 당일 실천의 실제 결과를 듣는다. 여러 작업의 주요 변화·사용자 관점·교정된 관계·남은 의문·채택한 행동을 보존한다 |

입력 원자료, 사용한 스킬 버전, 실제 질문·합성 사용자 답·다음 응답·최종 일기를 저장소 밖 임시 자료에 남겨 서로 대조한다. 가능하면 응답 생성·합성 답 제공과 독립 판정을 분리한다. 판정자는 기대 단어의 포함 여부보다 선택한 관계, 실제 받은 답, 예산, 최종 내용의 손실과 날조를 검토한다. 실패와 미실행도 남기며, 한 번의 비재현이나 개선본 통과로 성공률·장기 학습 효과를 주장하지 않는다. 개인 원문·경로·실행 식별자를 공개 파일에 넣거나 새 영구 실행기·DB를 만들지 않는다.

설치본 반영이 요청된 변경은 소스·PR 반영으로 끝내지 않는다. 현재 설치 경로와 독립 변경을 확인하고 백업한 뒤 해당 스킬만 갱신한다. 전체 파일 목록·내용을 비교하고, 새 평가 문맥에서 **설치 경로의 파일을 직접 읽어** 통합 문답을 최종 일기까지 생성했는지 확인한다. 소스 평가, 설치 파일 일치, 설치본을 읽은 평가를 구분해 보고한다. 기존 대화가 이미 읽은 내용이 바뀌었다고 가정하거나 다른 작업에 임의로 메시지를 보내지 않는다. 검증에 쓴 개인 경로·세션·원문은 공개 산출물에 넣지 않는다.
