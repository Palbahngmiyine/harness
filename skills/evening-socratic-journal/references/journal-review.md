# 지난 일기 조회와 월요일 검증

매 호출에 “일기 위치와 본문 확인”과 “호출일 계산과 실행 판정”을 읽는다. 이번 주 검증이 미완료이거나 사용자가 주간 회고를 요청하면 나머지도 읽는다. 일기 날짜, 호출일, 기준 월요일, 검증 기간을 구분하고 현재 날짜를 과거로 가장하지 않는다.

## 일기 위치와 본문 확인

1. 현재 대화의 저장 합의, 제공된 파일·링크, 이전에 확인한 일기 위치를 먼저 따른다. 위치가 아직 없으면 접근 가능한 최근 일기 대화의 저장 결과·합의에서 경로를 찾는다. 저장소 이름만 있으면 등록 프로젝트 목록(예: `list_projects`)으로 로컬 경로를 확인하고 그 저장소의 지침·README·일기 인덱스에서 실제 위치를 찾는다. 현재 작업 폴더가 일기 저장소라고 가정하지 않는다.
2. 로컬 후보는 확인된 저장소·일기 폴더 안에서 `rg --files` 등으로 날짜별 파일명을 찾는다. 날짜 폴더 하나만 보지 말고 필요한 월 경계를 포함한다. 연결된 문서 도구는 명시된 일기 페이지·데이터베이스 범위에 사용한다. 사용자 홈 전체·다른 계정·달력·메신저를 탐색하지 않는다.
3. 인덱스·검색 요약·파일명은 후보 단서다. 최근 일기의 **본문**을 읽어 실제 작은 선택, 예측, 후속 결과를 확인한다. 일기 날짜가 파일명·frontmatter·본문 사이에서 충돌하면 확정된 날짜의 근거로 쓰지 말고 충돌을 표시한다. 최신 기록이 다른 worktree나 PR에 있다는 근거가 있으면 등록 worktree·그 PR을 읽기 전용으로 확인한다. 최신화를 위해 checkout·pull·merge하지 않는다.
4. 기본은 대상 일기 날짜 이전의 가장 최근 기록과 거기서 연결한 후속 기록을 읽는다. 같은 날 재호출이면 당일 일기도 먼저 읽는다. 초안·복사본은 내용과 출처를 대조해 중복을 줄이고, 어느 것이 채택본인지 모르면 덮어쓰거나 임의로 선택하지 않는다.
5. 위치를 찾지 못하거나 권한이 없으면 그 범위를 알리고 위치만 질문하면서 오늘의 독립적인 문답을 계속한다. 본문을 읽지 못한 주간 검증은 `미실행`이다. 일기를 읽었지만 특정 행동의 결과 근거가 없으면 그 항목은 `미확인`이다. 기록이 없는 날을 미실행 행동이나 밀린 일기로 세지 않는다.

일기를 읽는 것은 과거 내용을 수정하거나 저장 위치를 새로 만들라는 권한이 아니다. 합의된 위치·기존 파일 규칙을 따르고 개인 경로·원문·작업 ID를 배포용 스킬에 고정하지 않는다.

## 호출일 계산과 실행 판정

1. 호출 시작 시 현재 시각을 날짜·시간 도구로 확인하고 사용자 시간대의 현지 날짜 `D`를 구한다. 날짜 도구나 표준 날짜 라이브러리로 요일 `w`를 **월=1, 화=2, …, 일=7** 기준으로 계산한다. 도구가 다른 번호 체계를 쓰면 변환한다. 일기 제목의 날짜나 기억으로 요일을 추정하지 않는다.
2. 이번 주의 기준 월요일 `M`은 **D에서 (w−1)일을 뺀 현지 달력 날짜**다. 기본 검증 기간은 **M의 7일 전 월요일 00:00 이상, M 00:00 미만**으로 고정한다. 화~일요일의 보충 검증도 같은 기간이며, 호출일 직전 7일로 옮기지 않는다. 월·연도·서머타임 경계에는 달력 날짜와 시간대를 사용한다. 대화 중 자정이 지나도 이 호출의 기준은 유지한다.
3. 알려진 일기 저장 범위에서 `M` 또는 해당 검증 기간이 일치하는 `주간 확인`·기존 `월요일 확인` 본문을 찾는다. 대상 날짜의 일기, 호출일의 일기, 최근 주간 기록과 연결된 저장 위치를 확인한다. 보충 검증이나 과거 날짜 일기 때문에 완료 기록이 월요일 파일 밖에 있을 수 있다. 파일명·제목만으로 완료 여부를 판단하지 않는다.
4. 아래 기준으로 이번 호출의 주간 검증을 결정한다. 실행 필요 여부가 정해지면 별도 참여 승인을 다시 묻지 않으며, 사용자가 생략하거나 중단하면 존중한다.

| 확인한 상태 | 이번 호출의 동작 |
|---|---|
| `M`에 해당하는 완료 기록이 있음 | 요일과 무관하게 주간 검증을 반복하지 않는다. 새 결과나 명시적 재검토 요청이 있으면 필요한 항목만 갱신한다 |
| 완료 기록이 없고 `w=1` | 이번 월요일의 주간 검증을 진행한다 |
| 완료 기록이 없고 `w=2~7` | 이번 주 월요일을 놓친 것으로 보고, 그 주의 첫 해당 호출에서 한 번 보충 검증한다 |
| 같은 주의 초안·진행 중 기록만 있음 | 완료로 세지 않고 남은 부분을 이어서 검증한다. 이미 확인한 답을 다시 묻지 않는다 |
| 기존 기록을 읽을 수 없어 완료 여부를 모름 | `완료 여부 미확인`으로 알리고 접근 가능한 기록을 더 확인한다. 접근 실패를 기록 부재로 바꾸거나 완료 표시를 만들지 않는다 |

다른 주의 완료 기록은 이번 주의 검증을 대신하지 않는다. 이번 주 검증 하나를 처리하며 여러 주의 누락을 자동으로 소급 수행하지 않는다. 주간 검증이 필요 없는 호출도 최근 실천과 확인 시점이 된 예측을 돌아볼 수 있다.

완료 여부는 **기준 월요일 또는 검증 기간, 읽은 근거, 검토 결과**로 판단한다. 새 기록에는 `완료 / 진행 중 / 미실행`을 명시한다. 상태 표기가 없는 기존 일기도 같은 기간의 검토를 마친 본문이 있으면 완료로 인정한다. 빈 양식, 예정 문구, 중단된 초안, 조회 실패는 완료본이 아니다. 개별 실천·효과가 `미확인`이어도 근거를 읽고 그 한계까지 정리해 검증을 마쳤다면 주간 검증은 완료일 수 있다. 일기 조회 자체가 실패해 검증하지 못했으면 완료로 남기지 않고 다음 호출에서 다시 판단한다.

해당 기간의 일기 본문에서 사용자가 채택한 실천과 예측을 모으고, 마지막 주간 기록이 연결한 항목 중 실제 호출일까지 확인할 시점이 된 것도 포함한다. 원래 주의 선택과 이후 관찰을 구분해 적는다. 제안만 있었던 행동은 약속으로 세지 않고, 철회·종료한 항목은 새 근거 없이 다시 과제로 만들지 않는다.

## 실행과 효과를 근거로 나눈다

지난주의 관련 항목을 읽고, 그중 결과 확인 시점이 된 항목을 우선한다. 대화는 영향이 크거나 설명이 어긋난 한 항목부터 시작하고 나머지는 확인된 상태를 짧게 남긴다. 시간 때문에 검토하지 못한 항목은 `이번 문답에서 미검토`로 구분한다.

| 기록할 내용 | 근거와 판정 기준 |
|---|---|
| 원래 선택·예측 | 원래 일기 날짜와 위치, 사용자가 채택한 행동·예측·조건·확인 예정일. 없던 약속이나 기한을 만들지 않는다 |
| 실행 여부 | `실행 확인 / 일부 실행 / 미실행 확인 / 미확인 / 철회`. 후속 일기의 사용자 진술·현재 답변·해당 행동의 직접 근거를 연결한다. 계획·assistant의 실행·기록 부재는 사용자가 수행했다는 근거가 아니다 |
| 실제 효과 | 실행과 별도로 관찰한 변화와 출처. 아직 효과가 나타날 시점이 아니면 `관찰 시점 전`, 관찰 자료가 없으면 `미확인`. 목표 달성이 그 행동 때문이라는 인과는 따로 검토한다 |
| 예측 대조 | 시점과 조건이 맞는 근거를 제시하고 사용자가 `적중 / 불일치 / 미확인`을 판단한다. 확인일 전에는 판정을 미루고, 조건이 달라졌으면 원래 예측과 분리한다 |
| 다음 개선 | `유지 / 축소 / 변경 / 철회`의 제안과 사용자 채택 여부. 채택하면 상황·최소 행동·확인 방법·다음 확인일을 남긴다. 미채택은 약속으로 쓰지 않는다 |

일반적인 회고 문장을 수행 증거로 과해석하지 않는다. 예를 들어 “다음번에는 검토하겠다”는 계획이고, “검토했고 빠진 조건 하나를 찾았다”는 사용자 진술에 근거한 실행과 결과다. 세션에서 LLM이 검토를 마친 것은 사용자가 결과를 확인하거나 이해했다는 증거가 아니다.

## 문답과 개선안

이미 후속 기록에 답이 있으면 읽은 근거와 판정을 먼저 요약하고 불분명한 부분만 한 번에 하나씩 묻는다. “지난 일기에 고른 이 행동은 이후 어떻게 되었나요?”로 시작하고, 답에 따라 실행 조건·효과·다른 설명 중 필요한 하나를 확인한다. 기억나지 않는 답을 실패로 바꾸지 않는다.

LLM 작업의 지난 예측을 확인할 때는 [역학 연습](dynamics-practice.md)의 “다음 저녁과 월요일의 확인”을 적용한다. 예상과 달랐다면 누락한 유입·유출·지연·피드백 또는 바뀐 조건을 사용자가 짚고 설명을 수정하도록 돕는다. 자료가 구조를 뒷받침하지 않으면 가설로 남긴다.

검증 근거가 있으면 개선안은 기본 하나만 제시한다. 효과가 있으면 유지, 부담 때문에 못 했다면 행동 축소, 조건이 바뀌었으면 방법 변경, 의미가 없어졌으면 철회를 검토한다. 결과가 미확인이면 확인 방법을 정하는 제안도 가능하다. 사용자가 선택하지 않거나 개선을 원하지 않으면 `개선안 미채택`으로 마친다.

지금 작성하는 대상 날짜 일기의 `주간 확인`에 **기준 월요일 M / 실제 검증일 D와 시간대 / 검증 기간 / 완료 여부**를 남기고, 읽은 출처·원래 선택·실행·효과·채택한 개선·다음 확인일을 연결한다. 화~일요일에 수행했다면 `보충 검증`이라고 적되 검증일을 월요일로 소급하지 않는다. 대상 일기 날짜가 달라도 실제 검증일을 별도로 명시하며 새 월요일 파일이나 별도 체크포인트를 만들지 않는다. 다음 호출은 이 기록을 읽어 같은 주의 재실행을 막는다.

출력 제한이 있으면 완료 여부와 기준 월요일을 허용된 본문 안에 요약한다. 저장은 기존 합의에 따르며, 파일 저장을 하지 않았다면 접근 가능한 이전 일기 대화의 완료 기록도 확인 근거로 사용한다. 읽지 못한 대화를 기억한다고 주장하지 않는다. 과거의 원래 선택·예측을 소급해 고치거나, 점수·적중률·연속 기록·별도 DB·자동 예약을 만들지 않는다.

## 변경 시 확인할 행동

월요일 미검증, 화요일 첫 보충 검증, 보충 완료 뒤 수~일요일 재호출, 다음 월요일의 새 주, 월·연도·시간대 경계, 과거 날짜 일기 속 완료본, 이전 주의 완료본만 있는 경우, 초안·조회 실패를 검토한다. 같은 주는 동일한 `M`과 기간을 사용하고 완료 뒤 반복하지 않는지 확인한다. 후속 기록에 답이 있으면 다시 묻지 않으며 기한 전 예측을 조기 판정하거나 제안을 약속으로 바꾸지 않는다.
