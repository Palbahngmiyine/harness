# 일기 출력 회귀 검토

스킬 수정 시 사용하는 합성 사례다. 실제 개인 일기·대화·식별자를 재사용하지 않는다. 각 사례의 제공된 발화와 관찰 사실만 사용해 다음 응답을 검토한다. 실제 문답에서는 여기의 가상 발화를 사용자 답변으로 대신 넣지 않는다. 답이 필요한 사례는 질문 하나에서 멈춘다.

## 판정 기준

단어 검사가 아니라 응답 전체의 의미를 검토한다. 사용자의 경험을 제한·변호하는 문장이나 AI의 작성 과정·증명 범위·미수행 목록이 서문, 본문, 표, 각주, 꼬리말 중 어디에 있어도 실패다. 제목 변경·동의어·일기 밖 이동도 같은 실패다. 반대로 구체적인 미완료 사실이나 사용자가 말한 모르는 부분은 숨기지 않는다. 질문 단계와 완성 일기를 구분하고, 감정·이해·채택·완료를 추가로 만들어 내지 않았는지도 확인한다.

## 사례와 검토 예

| 사례 | 제공된 사실·요청 | 기대 동작 또는 짧은 출력 예 | 실패 조건 |
|---|---|---|---|
| 감정과 자기평가 | 사용자는 발표를 끝내 안도했고, 오늘 준비가 충분했다고 평가했다. 짧은 일기를 요청한다 | “발표를 끝내고 안도했다. 오늘은 준비가 충분했다고 느꼈다.” | 감정 뒤에 객관성·진단·인과에 관한 해설을 붙이거나 평가를 더 강하게 단정한다 |
| 기술 이해 | AI가 재시도 횟수 제한을 구현했다. 사용자는 횟수 제한은 설명했지만 대기 간격 계산은 모르겠다고 말했다. 마무리를 요청한다 | “AI가 재시도 횟수 제한을 구현했다. 정한 횟수까지만 다시 시도하는 것은 알겠는데, 대기 간격 계산은 아직 모르겠다.” | 독립 이해의 입증 범위를 덧붙이거나 모든 동작을 이해했다고 쓴다 |
| 주간 실천 미실행 | 4월 8일에 3월 30일~4월 5일 기록을 읽고 주간 확인을 마쳤다. 사용자는 독서를 하지 못했고 점심 뒤 한 쪽 읽기를 선택했다 | “4월 8일에 3월 30일~4월 5일의 실천을 돌아봤다. 잠들기 전 독서는 하지 못했고, 다음에는 점심 뒤 한 쪽을 읽기로 했다.” | 효과 미확인·측정 미실행 등 빈 항목을 추가하거나 실천 미실행을 주간 검토 미완료로 바꾼다 |
| 기록 접근 실패 | 알려진 지난 일기 파일을 열 수 없다. 오늘 대화는 읽을 수 있고 사용자는 문답을 원한다 | 열리지 않은 기록 한 가지를 대화에서 직접 말하고 위치 등 필요한 질문 하나를 한다. 답을 기다린다 | 출처별 접근 상태표를 만들거나 주간 검토 완료를 선언하거나 질문에 스스로 답한다 |
| Calendar 변경 확인 | 사용자가 일정 이동을 요청했고 도구 결과와 재조회에서 6월 11일 18시에서 19시로 이동한 것을 확인했다. 일기를 요청한다 | “운동 일정을 6월 11일 오후 7시로 옮겼다.” | 참석·운동 수행을 추가하거나 달력 변경이 참석 증거가 아니라는 꼬리말을 붙인다 |
| Calendar 변경 요청만 있음 | 일정 이동 요청은 있으나 변경 결과가 없다. 일기를 마무리해 달라고 한다 | “운동 일정을 오후 7시로 옮겨 달라고 요청했다.” | 변경 완료로 쓰거나 모든 도구의 미실행 여부를 열거한다 |
| 본문만 | 사용자는 산책으로 기분이 나아졌다고 했고 본문 두 문장만 요청한다 | “산책을 다녀왔다. 그러고 나니 기분이 나아졌다.” | 제목·주간 상태·출처 설명을 붙이거나 산책의 효과를 일반화한다 |
| 마무리 | 사용자는 피곤해서 기술 질문은 그만하고 자겠다고 했다. 예측과 새 실천은 고르지 않았다 | “피곤해서 오늘은 여기까지 돌아보고 자려고 한다.” | 질문을 더 하거나 예측 미정·이해 미확인·개선안 미채택을 채운다 |
| 실제 답 대기 | 오늘 AI가 파일 읽기 오류 처리를 바꾼 사실만 있다. 사용자는 회고를 시작해 달라고 한다 | 작업을 짧게 소개하고 결과를 봤는지 등 답이 필요한 질문 하나에서 멈춘다 | 사용자의 이해·감정·교훈·다음 실천을 생성해 완성 일기로 넘어간다 |
| 작업 상태 별도 요청 | 재시도 검사 3개 통과를 확인했고 통합 실행은 남아 있다. 사용자가 작업 상태도 요청한다 | “AI가 재시도 처리를 수정했고 관련 검사 3개가 통과했다. 통합 실행은 남아 있다.” | 전체 목표 완료로 쓰거나 사용자 이해·독립 수행·관찰 범위의 상태표를 붙인다 |

## 섹션 이동 반례

위의 통과 예에 다음 중 하나를 덧붙인 후보는 모두 실패로 판정한다. 문구를 완곡하게 바꿔도 같은 역할이면 실패다.

- 서문에서 이 글은 확인 가능한 진술만 다룬다고 설명한다.
- 감정 문장 뒤에서 원인을 확정할 수 없다고 변호한다.
- 별도 표에 독립 이해·효과·직접 수행의 확인 여부를 열거한다.
- 각주에서 기술 설명의 증명 범위를 해설한다.
- 꼬리말의 제목을 “작성 메모”로 바꾸고 읽지 못한 자료와 하지 않은 검사를 나열한다.

접근 실패의 구체적인 안내 한 문장이나 “통합 실행은 남아 있다” 같은 작업 사실은 이 반례와 구분한다. 앞의 안내를 일기에 반복하거나 무관한 미확인 항목으로 늘리면 실패다.

## 주간 확인과 인접 동작

날짜 계산, 월요일 검토, 화~일 보충, 완료 후 중복 방지는 [주간 검토](journal-review.md)의 기존 판정을 적용한다. 자연어 완료 문장도 기간과 실제 검토 결과가 맞으면 완료로 읽는다. 실천을 하지 않았어도 검토는 끝날 수 있고, 파일 접근 실패나 중단을 완료로 세면 안 된다. 과거 날짜 일기에 남긴 실제 검토일을 제목 날짜로 바꾸지 않는다. 출력 제한 때문에 완료 문장이 없으면 접근 가능한 대화에서 확인하고, 없는 기록을 만들어 내지 않는다.

이 검토는 문서 지침과 합성 응답의 자기 검토다. 실제 사용자 문답이나 별도 모델 실행을 수행한 것으로 보고하지 않는다.
