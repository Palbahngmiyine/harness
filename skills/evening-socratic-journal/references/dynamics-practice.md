# 시간에 따른 변화를 직접 검토하는 연습

`SKILL.md` 2절에서 문제 선택·연습 과정·완료 판정을 읽는다. 모델이 필요하면 “작은 모델로 대조하기”, 재개할 때는 “여러 날의 누적과 유지·전이”를 읽는다. 연구 근거를 점검할 때만 [출처와 설계 범위](design-sources.md)를 읽는다.

목표는 사용자가 문제의 범위를 정하고, 상태와 결정 규칙의 연결로 시간 경로를 예상하며, 결과와 비교해 설명과 정책을 고치는 것이다. 요소 이름을 말하거나 AI가 준 두 흐름을 빼는 것은 기초 확인일 수 있으나 이 전체 목표를 대신하지 않는다. 시간·질문 수 상한이나 매일의 용어 목록을 두지 않는다. 아래 흐름은 답에 따라 오가는 과정이며 모두 매일 처음부터 수행하는 순서표가 아니다.

이 문서의 진행·지도 여부는 내부 판단용이다. 일기에는 실제 답과 변화한 생각을 자연스럽게 남기고 상태표·평가 해설을 붙이지 않는다.

## 문제 선택과 학습자 출발점

AI는 관찰 가능한 시간 변화와 아직 풀리지 않은 판단이 있는 사건을 준비한다. 사용자에게 중요한 질문이 무엇인지, 어떤 양의 어느 기간 변화를 보면 그 질문을 검토할 수 있는지 먼저 듣는다. 변수·시스템 경계·피드백·해법을 모두 제시한 뒤 숫자만 묻지 않는다. 사용자가 이미 문제를 정했으면 재확인용 질문을 반복하지 않는다.

정책을 비교하기 전에 사용자의 우선 목표를 정한다. 필요하면 목표값, 허용 하한·상한, 행동을 시작하는 기준, 모델을 계산할 수 있는 범위를 구분한다. 급수 시작 기준이 곧 반드시 유지할 최소량인 것은 아니며, 계산 범위가 곧 허용 범위인 것도 아니다. 모든 문제에 수치 경계나 비용함수를 요구하지 않는다. 도중에 하한이나 목표를 새로 채택하면 무엇이 바뀌었는지 밝히고 앞선 정책 결론을 새 기준으로 다시 대조한다.

- 실제 관측, 코드의 갱신 규칙, 사용자가 관찰한 장면에서 시작한다. 서로 다른 크기의 입력을 각각 한 번 처리한 비용 비교만 있다면 정적 비교다. 시간 단위·반복문·합계가 있다는 이유로 역학이라고 부르지 않는다.
- 같은 시스템의 이전 상태가 다음 상태와 다음 결정에 어떻게 영향을 미치는지 볼 수 있어야 한다. 예: 저장량과 생성·삭제, 지연된 관측에 따른 조절, 실패가 재시도와 부하를 통해 실패에 되돌아오는 관계.
- 사용자의 질문에 필요한 경계를 함께 정한다. 포함할 상태·외부에서 주어진 조건·제외한 과정과 그로 인한 한계를 구분한다. 실제 이해도·감정·생산성을 근거 없는 수치로 만들지 않는다.
- 지난 일기에서 실제로 설명한 부분과 남은 질문을 읽는다. 기초를 이미 이해했다면 그것을 사용해 미해결 관계나 정책으로 바로 진행한다. 실제 답의 오류·근거 공백·모름에 맞춰 필요한 부분을 지도한다. 자신 있게 답했어도 근거와 어긋나면 대조하고 교정한다. 이전 AI의 “이해했다”는 평가는 답을 대신하지 않는다.
- 실제 자료가 부족하면 같은 문제의 관련 자료를 작은 범위에서 보완한다. 그래도 검토가 어려우면 “실제 규칙이 없어 가정한 모델로 먼저 살펴보겠습니다”라고 구분한다. 모델의 수치·사건을 실제 작업의 관측으로 옮기지 않는다. 대기열 등 한 소재를 고정 기본값으로 쓰지 않는다.

## 답에 따라 발전시키는 연습 과정

한 번에 실제 질문 하나를 하고 답을 기다린다. 표의 여러 항목을 한꺼번에 묻지 않는다. 질문 순서는 사용자가 이미 제공한 내용과 가장 중요한 미해결 판단으로 고른다.

| 필요한 판단 | 사용자에게 맡길 일 | AI의 지원과 다음 행동 |
|---|---|---|
| 문제와 시간 경로 | 원하는 결과, 관찰할 양·기간·경계, 현재와 바라는 경로를 정한다 | 관찰 사실을 짧게 제공한다. 처음부터 모든 변수와 답을 정하지 않는다 |
| 상태와 결정 | 어느 시점의 양, 그 양을 늘리고 줄이는 흐름, 누가 무엇을 보고 언제 행동하는지 설명한다 | 단위·빠진 유출·외부 조건 등을 필요한 만큼 확인한다. 이미 맞힌 뺄셈은 반복하지 않는다 |
| 구조 결합 | 결과가 다음 결정을 바꾸는 연결, 행동/관측 지연, 용량 한계 등이 경로를 어떻게 바꾸는지 설명한다 | 사례에 필요한 관계만 결합한다. 근거 없는 루프나 비선형성을 추가하지 않는다 |
| 예측과 정책 | 현재 규칙과 자신이 고른 대안 아래 가까운 시점·중간·이후의 경로와 이유를 예측한다 | 결과 계산이나 정답 곡선은 이 답 뒤에 제시한다. 정책의 목표·부작용·유효 조건을 구체화한다 |
| 결과 대조 | 예측과 관찰/모델 결과의 차이, 원래 가정 중 바꿀 것을 짚는다 | 검증 가능한 결과를 제시한다. 자료가 부족하면 정오를 꾸미지 않는다. 적중해도 다른 원인으로 같은 결과가 가능한지 본다 |
| 수정과 재적용 | 설명 또는 정책을 수정하고, 지원을 줄인 조건에서 다시 구성·예측한다 | 틀린 부분에만 지도한다. 앞 풀이를 숨기고 경계·관측 방식·결정 규칙 등 실질 조건을 바꾼 문제를 준다. 답의 실제 근거로 지원을 조절한다 |

여러 시점은 시점 수를 채우라는 뜻이 아니다. 지연 이전과 이후, 초반 증가와 나중 감소처럼 경쟁 설명·정책의 결과가 갈리는 경로를 보도록 고른다. 변수 하나의 숫자만 바꾸어 같은 계산을 반복했다면 기초 적용으로 남긴다.

### 오답·모름·그럴듯한 정책

오답은 부족한 연결이나 가정을 찾을 단서다. “다시 생각해 보세요”를 반복하지 않는다. 확인된 규칙·한 구간의 계산·간단한 그림 중 필요한 도움을 주고 아직 풀지 않은 부분은 실제로 답하게 한다. 정의가 필요하면 먼저 짧게 가르쳐도 된다. 용어를 스스로 발견해야만 진행할 수 있는 장벽을 만들지 않는다.

부분 답에는 빠진 연결 하나를 묻는다. 모른다고 하면 어디까지는 판단할 수 있는지 확인하거나 그 부분을 보여 준 뒤 새로운 판단을 맡긴다. “알겠습니다”나 AI 설명의 복창은 수정된 이해의 증거로 충분하지 않다. 첫 설명, 지도한 내용, 지도 뒤 실제 답을 구분한다.

정책이 그럴듯해도 목표에 맞는지 시간 경로로 검토한다. 예를 들어 늦은 관측 때문에 계속 개입하는 정책은 관측이 따라온 뒤의 상태도 예상하게 한다. 무조건 기다리기가 정답이라고 유도하지 않는다. 기다리는 동안 손실이 커지는 조건, 지연이 없는 조건 등 모델 안에서 가능한 반례로 대안을 비교한다. 실제 장치나 생활을 바꿔 실험하는 권한은 연습에서 자동으로 생기지 않는다.

## 작은 모델로 대조하기

말·표·시간 그래프·상태/흐름 그림·인과 루프 그림·수치를 필요에 맞게 사용한다. 그림은 관계를 외부에 표현하는 보조이며 그 자체로 동적 결과를 검증하지 않는다. 사용자의 초안에서 빠진 관계를 함께 보완할 수 있다. 그래프를 읽기 어려우면 같은 내용을 표나 말로 바꾸되 이해 문제와 표현 해독 문제를 구분한다.

기존 코드·모델·계산 도구가 있으면 해당 범위에서 활용한다. 도구가 없어도 손으로 독립 확인할 수 있는 작은 이산시간 모델을 쓸 수 있다. 수치 예시를 원자료·측정값처럼 제시하지 않는다. 모델이 질문을 검토하기에 부적절하면 범위를 줄이거나 관찰 대기로 남긴다. 이 스킬에 별도 실행기·설정·상주 시스템·DB를 추가하지 않는다.

모델 결과를 제시하기 전에 다음을 확인한다.

- 목적, 포함/제외 범위, 상태와 흐름의 단위, 한 단계의 시간 간격, 초기 상태와 지연 중인 양/관측값을 명시한다.
- 정책의 좋고 나쁨을 판단할 시점·목표와 허용 범위를 구분한다. 표의 관측 시점 사이에 생기는 최대·최소도 판단에 중요하면 확인한다. 급수 직전 값만으로 직후의 과잉이 없다고 결론내리지 않는다.
- 관측 → 결정 → 적용 → 상태 갱신의 순서와 지연 규칙을 고정한다. 이전 상태와 새 상태를 섞지 않는다. 유량(양/시간)은 시간 간격을 곱해 양으로 바꾼다.
- 음수·용량 초과·유출 제한 등 경계 처리를 명시한다. 한계를 잘라낸 양이 어디로 가는지도 보존 관계에 맞게 설명한다.
- 기본 정책과 대안은 같은 초기조건·외부 조건에서 비교한다. 학습자의 예측 뒤에 실제 계산한 여러 시점의 결과를 보여 준다.
- 한 단계는 수작업으로 재계산하고, 전체 경로는 도구 또는 별도 계산으로 대조한다. 다른 시간 간격을 쓰면 지연과 단위도 함께 바꾼다. 근거 없이 모델을 현실에 보정했다고 말하지 않는다.
- 매개변수·초기조건·지연 유무·외부 유입 등 정책 판단에 중요한 가정을 바꿔 결론이 유지되는지 확인한다. 곡선 하나가 맞았다는 이유로 모델을 확정하지 않는다.

### 합성 모델 예시: 늦게 반영되는 자동 보충

유지보수자가 계산 가능성을 확인할 예시이며 매일 이 모델을 읽어 주지 않는다. 아래 결과는 사용자 예측 전에 보여 주지 않는다. 실제 문답에서는 사용자의 문제·변수 선택 후 필요한 가정을 함께 정한다.

한 구간은 하루다. 하루 시작 보유량 S(t)의 단위는 L, 목표는 10 L, 매일 소비는 2 L/일이다. 시작 보유량 S(0)=10, 당일 도착 예정 A(0)=2 L. 당일 시작의 보유량을 보고 주문 O(t)를 정하고, 그날 A(t)가 도착한 뒤 2 L를 소비한다. 주문은 다음 날 도착하므로 A(t+1)=O(t). S(t+1)=S(t)+A(t)−2. 물리 경계는 S(t)+A(t)≥2인 구간만 사용하며 이 조건이 깨지면 모형 적용 밖으로 알리고, 음수 재고로 조용히 계산하지 않는다. 주문은 음수가 될 수 없다. 증발·용량 제한·배송 변동은 제외했다.

목표 차이만 보고 기본 소비도 보충하는 정책 O(t)=max(0, 2+10−S(t))를 생각한다. S(0)=10이면 S(t)는 계속 10이다. 초기 보유량만 8 L로 바꾸면 시작 보유량 t=0…6은 8, 8, 10, 12, 12, 10, 8 L가 되고 주문 t=0…5는 4, 4, 2, 0, 0, 2 L가 된다. 같은 지연을 무시한 보충이 반복돼 목표 위아래로 움직인다. 이는 가정한 규칙의 계산 결과이며 실제 공급 시스템의 주기 보장이 아니다.

도착 예정량을 반영하는 대안 O(t)=max(0, 2+10−(S(t)+A(t)−2))은 같은 초기조건에서 S(t)=8, 8, 10, 10, 10, 10, 10 L다. 대안의 식을 정답으로 먼저 주지 말고 학습자가 무엇을 보고 주문을 조절할지 선택하게 한다. 이후 실제 모델에서 규칙을 명확히 하고 계산한다. 더 빠른 보충이나 다른 소비 조건에서 어느 정책이 유리할지 재검토할 수 있다. 실질 조건을 바꾼 재적용에서는 이 대안 식을 다시 제공하지 않는다.

## 완료 판정

하루의 마무리와 학습 전체의 숙달을 분리한다. 다음은 내부 판단이며 사용자에게 점수표로 내보내지 않는다.

- **기초 확인:** 상태와 흐름 또는 지연 하나를 설명·계산했다. 오류를 고쳤어도 이것만으로 통합 문제를 완료하지 않는다. 다음 판단에 사용한다.
- **의미 있는 단위 완료:** 선택한 문제에서 학습자가 범위·상태·결정의 연결을 구성/보완했고, 필요한 구조를 이용해 여러 시점의 경로와 정책을 예상했으며, 검증 가능한 관찰/명시적 모델 결과에 비춰 설명·정책을 검토했다. 불일치가 있으면 실제 수정 답을 받는다. 마지막으로 풀이 지원을 줄인 재적용을 해 보아 무엇을 스스로 할 수 있고 어디에 도움이 필요한지 확인한다. 모든 구조를 넣을 필요는 없다.
- **부분 수행·관찰 대기:** 아직 모델을 만들지 못했거나 결과가 나중에 관찰되거나 재적용에서 막혔다면 그 질문을 남긴다. 필요한 지도 후에도 같은 막힘이 이어지면 더 많은 유사 질문으로 밀어붙이지 않고 그 지점에서 마무리할 수 있다. 단위 완료로 바꾸지 않는다.
- **유지·전이:** 시간이 지난 뒤 해설 없이 같은 구조를 재구성한 답은 유지의 관찰, 다른 맥락에서 경계·구조·정책을 새로 구성한 답은 전이의 관찰이다. 동일 세션 재적용·숫자 교체·지도 후 정답과 구분한다. 합성 세션으로 실제 인간의 효과를 확정하지 않는다.

단위를 마쳤으면 새 기법·두 번째 완결 문제를 계속 추가하지 않고 생활 회고와 일기로 넘어간다. 사용자가 계속 탐구하길 원하면 이어 간다. 중단·생략·간소화 요청은 완료 조건보다 우선한다. 대답이 없으면 응답 대기이며 AI가 답을 채우지 않는다.

## 여러 날의 누적과 유지·전이

별도 진도 DB나 숨은 파일을 만들지 않는다. 기존 일기의 실제 문장과 접근 가능한 대화에서 문제·경계·첫 예측·대조 결과·수정한 설명/정책·남은 의문을 읽는다. 일기에 질문 전체나 평가 항목을 복제하지 않고 재개에 필요한 내용을 장면에 남긴다. 실제 약속을 채택했을 때만 관찰 날짜·방법을 함께 적는다.

다음 날에는 전날 남긴 판단이나 관찰부터 이어 간다. 매일 새 기초 문제로 초기화하거나 “어제 이해했다”는 AI 요약을 그대로 믿지 않는다. 관찰 시점 전에는 실패로 판단하지 않는다. 적중하면 이유가 맞았는지, 불일치면 가정·조건·계산 중 무엇이 달랐는지 사용자 답으로 검토한다. 미관찰은 오답이 아니다. 철회한 예측을 밀린 과제로 쌓지 않는다.

재개 안내에는 문제·당시 목표·아직 확인하지 못한 질문을 필요한 만큼만 말한다. 예를 들어 “지난번 자동 보충에서 남긴 판단을 이어 보겠습니다”로 시작할 수 있다. 핵심 인과 관계, 빠뜨렸던 변수, 정답 정책이나 계산식을 먼저 복습시키지 않는다. 유지·전이를 확인할 때는 이전 풀이를 보여 주지 않은 채 관련 문제를 주고 사용자의 첫 구성·예측을 실제로 받는다. 답이 막히거나 오류가 있으면 그 뒤에 단서를 제공하고 지원된 답으로 구분한다. 사용자가 복습 설명을 먼저 요청하면 설명하되 이어진 정답을 도움 없는 확인으로 세지 않는다. 새 문제와 낯선 용어를 이해하는 데 필요한 사실까지 숨기지는 않는다.

문제가 충분히 검토됐고 다음 실제 사건에 관련 구조가 나타나면 해설을 먼저 주지 않고 적용하게 한다. 필요하면 서로 다른 사례의 경계와 중요한 차이를 사용자가 짚게 한다. 주간 확인에서는 관련된 이전 예측과 연결해 시간이 지난 설명·정책 판단을 볼 기회를 갖는다. 매일 모든 단계나 정해진 횟수의 재시험을 강제하지 않는다. 유지를 실제로 확인하지 않았다면 완료를 앞당겨 쓰지 않는다.

사용자가 학습을 생략·거절한 경우 새 재개 요청 전에는 다시 권하지 않는다. 단순 작업 전환 뒤 복귀나 미완료 지적은 `SKILL.md`의 재개 규칙을 따른다.

## 여러 날 이어지는 자율 작업에서 배우기

오늘 참여하지 않은 작업도 확인된 당일 변경과 남은 일을 짧게 소개하고 결과를 봤는지 묻는다. 이미 답한 사실은 반복하지 않는다. 전날 누적 성과를 오늘의 수행으로 바꾸거나 읽지 않은 전체 프로젝트를 설명하게 하지 않는다.

사용자 의도·오늘의 변경·관찰된 경로를 학습 문제에 연결한다. 정적 변경밖에 없어 가상 모델을 다뤘다면 실제 작업 변화와 가상 연습에서의 이해를 각각 자연스럽게 기록한다. 전체 목표의 남은 구현 과제나 AI가 세운 실험을 사용자의 약속으로 바꾸지 않는다.

## 용어와 범위

필요할 때 짧게 정의한다. 스톡은 특정 시점의 축적량, 플로우는 시간당 그 양을 늘리거나 줄이는 흐름, 피드백은 상태의 변화가 결정과 행동을 거쳐 그 상태에 다시 영향을 주는 연결, 지연은 행동·물리적 반영·관측 사이의 시차다. 비선형성은 입력 변화에 대한 반응 비율이 일정하지 않은 관계이며 실제 용량·임계값 근거가 있을 때 다룬다.

구조 이름이나 시스템 원형·개입 지점 순위를 사용자 삶의 진단으로 붙이지 않는다. 개인 성격·능력·질환을 추정하지 않는다. 두 생활 영역을 한 원인으로 묶지 않으며 밖의 경험으로 학습을 확장하는 것은 사용자의 의사를 따른다.

수정 후 [합성 행동 검토](behavior-checks.md)와 [일기 출력 회귀 검토](output-review.md)를 적용한다. 연구의 직접 결과와 이 스킬의 가설적 적용은 [설계 출처](design-sources.md)에서 구분한다.
