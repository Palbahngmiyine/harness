# 역학 연습 진행표

`SKILL.md` 2절에서 LLM 작업을 돌아볼 때 “LLM 작업 이해를 맞추는 문답”과 필요한 요소·예측 형식을 읽는다. 지난 예측을 검증할 때는 “다음 저녁과 월요일의 확인”을 읽는다. 매일 전체를 다시 읽거나 각 절의 질문을 모두 하지 않는다.

역학 연습은 LLM이 한 일의 작동 방식과 결과를 사용자가 설명하고, 기록 근거와 비교해 이해를 수정하는 약 3분의 문답이다. 하루 한 사건의 요소 하나만 다루며, 2절의 첫 질문과 결과 확인 질문을 포함해 다섯 질문을 넘기지 않는다. AI는 사용자의 첫 설명 전에 모범 답안을 주지 않는다. 설명 뒤에는 근거가 있는 오류를 짧게 교정할 수 있으며, 사용자가 다시 설명할 기회를 준다. 이 연습의 장기 학습 효과를 입증한 것은 아니다. 근거와 한계는 [출처와 설계 범위](design-sources.md)에 있다.

이 문서의 이해·검증 상태는 내부 판단용이다. 일기에 상태표나 증명 범위 해설로 옮기지 않으며 `SKILL.md`의 “일기 전체의 문체”를 따른다.

## 역학 질문을 시작할 사건 선택

**먼저 관계를 고르고, 그 관계로 설명과 조건 예측을 모두 물을 수 있을 때 질문을 시작한다.** 읽은 근거에서 어느 시점의 상태가 다음 시점에 어떻게 바뀌는지, 그 사이 무엇이 늘거나 줄게 하는지 또는 언제 반영되는지를 짚는다. 같은 시간축 위의 상태·변화 원인·대조 근거·바꿀 조건 하나가 이어져야 한다.

| 자료에 있는 관계 | 선택할 문답 |
|---|---|
| 크기가 다른 배치를 각각 한 번 실행한 처리 시간·비교 횟수 | 입력 크기와 비용의 정적 비교다. 시간 단위가 있거나 합계가 증가해도 이것만으로 시간에 따른 상태 변화는 아니다. 다른 관계를 고른다 |
| 실행 중 남은 버퍼가 새 할당과 해제로 바뀜 | 같은 기간의 유입·유출로 다음 시점의 남은 양을 설명하고, 한 흐름을 바꿔 예측한다 |
| 작업 완료와 화면 반영 사이에 갱신 주기가 있음 | 실제 상태와 관찰 상태를 구분하고, 갱신 전에 다시 행동하거나 주기를 바꾸면 생길 차이를 예측한다 |
| 실패 증가가 재시도를 늘리고 재시도가 다시 부하·실패에 영향을 줌 | 결과가 다음 행동을 바꾸고 원래 상태로 돌아오는 연결을 설명하고, 한 연결을 바꿔 예측한다 |

알고리즘도 실행 단계 사이에 유지되는 상태와 갱신 근거가 있으면 선택할 수 있다. 단순 반복 횟수·복잡도 계산·구현 정책의 장단점에서 끝나는 사건은 작업 이해용이다. 근거 없는 업무량·이해도·감정 점수를 만들어 역학 관계로 쓰지 않는다.

관계가 없으면 이미 읽은 같은 작업의 다른 부분, 이어 다른 사건을 살핀다. 추가 조회는 관련 자료의 작은 구간 한 번으로 제한한다. 그래도 없거나 기록에 접근할 수 없으면 실제 사건과 구분해 “시간 변화 자료가 없어 짧은 가상 상황으로 연습하겠습니다”라고 말하고 연습을 시작한다. 별도 참여 승인을 반복하지 않는다.

가상 상황은 오늘 다루려던 관계와 최근 연습에서 남은 의문에 맞춰 고른다. 예를 들어 저장 공간의 생성·삭제, 일정 간격으로만 반영되는 표시, 지연된 관측에 따라 조절하는 처리량을 쓸 수 있다. 대기열을 기본 고정 소재로 삼지 않는다. 관찰 간격·증감 또는 갱신 규칙을 짧게 명시하고, 하나의 조건만 바꿔 비교할 수 있게 한다. 낯선 소재 설명에 질문을 소모하지 않는다. 실제 자료가 충분하면 가상 상황으로 바꾸지 않는다.

## LLM 작업 이해를 맞추는 문답

사용자 의도와 AI의 당일 변경·관찰 결과를 짧게 소개한다. 측정값·실행 시점·갱신 규칙은 답에 필요한 사실로 제공할 수 있다. 그 사실에서 도출할 변화 방향과 이유는 첫 답 전에 설명하지 않는다. 사용자가 이미 답한 부분은 반복하지 않고 한 번에 질문 하나에서 답을 기다린다.

질문은 첫 결과 확인을 포함해 최대 다섯 개다. 배경 확인은 필요할 때만 쓰고 최대 두 개로 제한한다. **변화 설명, 조건 예측, 필요한 교정에 질문을 남겨 둔다.** 구현 지식이나 산술 오류를 모두 고치는 것이 이 문답의 목표는 아니다.

1. **변화 설명:** 고른 상태가 관찰 기간에 어떻게 변하며 왜 그런지 사용자 말로 듣는다. 축적이면 같은 기간의 유입과 유출, 지연이면 실제 변화와 반영 시점, 피드백이면 결과가 다음 행동을 통해 원래 상태를 다시 바꾸는 연결을 묻는다.
2. **조건 예측:** 첫 설명을 근거와 대조한다. 맞으면 처음 고른 상태와 시간 관계를 유지하고 원인 조건 하나만 바꿔, 같은 관찰 시점의 상태·변화 방향 또는 반영 시점과 이유를 묻는다. 예를 들어 갱신 주기를 바꿨다면 같은 시각 화면에 무엇이 보일지를 사용자가 예측하게 한다. 변경한 규칙만 제시하고 그로부터 도출될 표시 상태·결과 시점을 먼저 알려주지 않는다. 정확한 배수나 합계보다 원인 관계를 기본으로 한다. 설명이 틀리거나 “모름”이면 아래 교정을 적용한 뒤 같은 예산에서 이어 간다.
3. **대조와 마무리:** 실제 코드·문서·관찰 또는 명시한 가상 규칙에 비춰 예측을 확인한다. 실제 자료가 부족하면 정오를 단정하지 않는다. 틀린 부분은 교정하고 실제 수정 설명을 받은 범위만 기록한다.

### 오답과 모름에 대응하기

부분 답이면 빠진 관계 하나만 확인한다. 구현 방침·용어·동의만 답했다면 그 내용에서 시간 변화의 이유가 아직 나오지 않았음을 짧게 짚는다. 정책 요약의 정확성과 역학 관계 설명은 별개다.

모름이나 오답이 이어지면 확인된 관계를 작은 부분으로 설명하고, 수치 계산 대신 질적인 변화와 이유를 한 문장으로 확인한다. 설명을 그대로 복창시키기보다 바꾼 조건에서 그 관계가 어떻게 적용되는지 묻는다. 이 질문에 수정 설명과 조건 예측이 함께 담겨 있으면 별도 문항으로 다시 묻지 않는다. 학습자의 답을 대신 만들어서는 안 된다.

남은 질문으로 설명·예측을 다 확인할 수 없으면 빠진 관계 하나만 다루고 종료 시 그 의문을 보존한다. 다섯 질문을 다 썼으면 추가 학습 질문 없이 다른 회고나 요청된 일기로 넘어간다. 새로운 사건·가상 상황·생활 소재를 골라 질문 수를 초기화하지 않는다. 피로·명시적 생략·중단·대기는 `SKILL.md`의 전환 규칙을 따른다.

### 완료 판정

실제 받은 답에서 **시간 변화의 관계 설명과 조건 변화 예측**을 찾아 각각 근거와 대조한다. 예측은 처음 고른 시간 관계가 변경 조건에서 어떻게 달라지는지에 대한 답이어야 한다. 지연의 결과를 AI가 제시한 뒤 버튼 동작만 묻는 식으로 별개의 정적 규칙을 확인했다면 그 시간 관계의 예측은 아직 남아 있다. 불일치가 있었다면 교정 뒤 사용자가 수정한 관계 설명도 있어야 해당 요소의 연습을 완료로 본다. 이를 내부에서 판단하며 용어 사용, 정책 요약, 단순 동의나 AI가 설명한 답으로 빈 단계를 채우지 않는다. 근거가 없으면 설명 미검증, 답을 받지 못했으면 응답 대기, 일부 답만 있으면 일부 수행으로 유지한다.

첫 답·AI 지도·지도 뒤 실제 답을 구분한다. 지도 후 해당 조건을 맞힌 것을 독립 전이 또는 장기 학습 효과로 넓히지 않는다. 일기에는 사용자가 실제로 설명·수정한 관계와 남은 구체적인 의문을 장면에 연결한다. 상태표나 증명 범위 해설은 붙이지 않는다. 가상 사건·수치는 실제 작업 결과나 미래 약속으로 옮기지 않는다. 연습 속 조건 예측과 사용자가 선택하는 실제 후속 관찰·실천 약속은 별개다.

## 여러 날 이어지는 자율 작업에서 배우기

오늘 참여하지 않은 장기 작업도 확인된 당일 변경을 두세 문장으로 소개하고 위 사건 선택을 적용한다. 이전 상태·오늘 바뀐 내용·아직 남은 문제를 구분한다. 결과를 봤는지 이미 답했다면 다시 묻지 않고, 전체 프로젝트나 읽지 않은 코드를 설명하게 하지 않는다.

동적 관계가 있는 변경에서는 사용자 의도, 오늘의 변경, 사용자가 설명·예측·수정한 관계를 연결한다. 정적 변경뿐이라 가상 연습을 했다면 실제 변경과 가상 연습에서 말한 이해를 각각 자연스럽게 기록한다. 전체 목표의 남은 구현 과제를 사용자의 실천 약속으로 바꾸지 않는다.

## 용어

이 문서 안에서 쓰는 이름이다. 사용자 앞에서는 오른쪽 열의 말로 묻고, 사용자가 요소를 자기 말로 짚은 뒤에 “이 연습에서는 그것을 스톡이라 부릅니다”처럼 한 번만 이름을 붙인다. 정의를 먼저 가르치지 않는다.

| 이름 | 뜻 | 사용자에게 묻는 말 |
|---|---|---|
| 스톡 | 시간이 지나며 쌓이거나 줄어드는 양. 어느 시점에 얼마나 있는지 말할 수 있다 | “시간이 지나면서 쌓였거나 줄어든 것” |
| 플로우 | 일정 기간 동안 스톡을 늘리거나 줄이는 양 | “그것을 늘린 일과 줄인 일” |
| 지연 | 행동과 그 결과가 보이기까지의 시차 | “결과가 언제쯤 보일지” |
| 강화 루프 | 변화가 같은 방향의 변화를 더 키우는 순환 | “늘어나자 더 늘리는 일이 생겼는지” |
| 균형 루프 | 변화를 어떤 수준으로 되돌리는 순환 | “늘어나자 줄이는 일이 생겼는지” |
| 정책 저항 | 선택이 다른 사람·조건·본인의 반응으로 약해지거나 뒤집히는 일 | “이 선택에 무엇이 어떻게 반응할지” |
| 멘탈 모델 | 상황이 어떻게 움직이는지에 대해 사용자가 머릿속에 갖고 있는 설명 | (직접 쓰지 않는다) |
| 상관 휴리스틱 | 들어오는 양의 오르내림이 쌓인 양의 오르내림과 같을 것이라고 짐작하는 습관. 들어오는 양이 줄어도 나가는 양보다 많으면 쌓인 양은 계속 는다 | (직접 쓰지 않는다. 점검 질문으로만 다룬다) |

## 진행표

아래 단계는 질문 난도를 고르는 안내다. 이전 일기에 단계가 있으면 참고하되 오늘 작업과 사용자의 답에 맞는 요소 하나를 고른다. 기록이 없으면 오늘 근거로 설명 가능한 기초 관계를 고른다. 모든 단계를 매일 수행하거나 단계 확인만을 위한 질문을 더하지 않는다.

| 단계 | 요소 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1 | 스톡과 플로우 | 스톡과 플로우를 구분해 말했고, 결과 근거와 비교할 수 있으며, 다음 요소가 오늘 작업 이해에 필요하다 |
| 2 | 지연 | 시차가 있는 예측을 한 번 이상 확인했고, 사용자가 다음을 원한다 |
| 3 | 순환 | 순환 안의 스톡을 짚었고 반례를 확인했으며, 사용자가 다음을 원한다 |
| 4 | 정책 저항 | 마지막 단계다. 반복하거나 1단계로 돌아가 다른 스톡을 고른다 |

### 1단계: 스톡과 플로우

- 목표: 오늘 사건 하나에서 쌓이거나 줄어든 양 하나와 그것을 늘린 것·줄인 것을 사용자가 자기 말로 짚는다.
- 질문 예시: “오늘 이 일에서 시간이 지나면서 쌓였거나 줄어든 것이 있나요?” “그것을 늘린 일과 줄인 일은 각각 무엇이었나요?” “지금 그 양은 어제보다 많은가요, 적은가요, 비슷한가요?”
- 사용자가 만드는 것: 스톡의 이름 하나(사용자 표현), 늘리는 것 하나, 줄이는 것 하나, 지금 방향.
- 점검 질문(한 개만): “늘리는 일이 줄어들면 쌓인 양도 바로 줄어드나요, 아니면 한동안 더 늘 수 있나요?” 또는 “쌓인 양이 줄기 시작하려면 무엇이 무엇보다 커져야 하나요?” 첫 답을 받은 뒤 유입·유출의 상대적인 크기와 대조한다. 불일치가 있으면 같은 질문을 반복하지 말고 근거로 교정한다.

### 2단계: 지연

- 목표: 오늘 한 행동과 그 결과 사이의 시차를 사용자가 짚고, 시차 때문에 달라진 판단을 살핀다.
- 질문 예시: “오늘 한 그 선택의 결과는 언제쯤 보일 것 같나요?” “지금 보이는 결과는 언제 한 행동에서 온 것인가요?” “결과가 아직 안 보인다는 것을 오늘 어떻게 해석했나요?”
- 사용자가 만드는 것: 행동 하나, 기대하는 결과 하나, 예상 시차(며칠 안·몇 주 뒤·모름 가운데 하나), 그 시차 동안 할 일.
- 점검 질문(한 개만): “결과가 보이기 전까지 같은 행동을 계속 늘리면 결과가 보일 때 어떻게 될까요?” 또는 “아직 결과가 없다는 것과 효과가 없다는 것은 어떻게 구분하나요?”

### 3단계: 순환

- 목표: 오늘 사건에서 변화가 스스로를 키웠는지(강화 루프) 어떤 수준으로 되돌렸는지(균형 루프) 한 순환을 사용자가 말로 서술하고, 그 안에서 쌓이는 것을 짚는다.
- 질문 예시: “그 양이 늘어나자 그것을 더 늘리는 일이 생겼나요, 줄이는 일이 생겼나요?” “그 순환에서 쌓이는 것은 무엇인가요?” “그 순환을 멈추거나 되돌린 것이 있었나요?”
- 사용자가 만드는 것: 두 요소 이상의 순환 한 개를 한 문장으로(“A가 늘면 B가 늘고, B가 늘면 A가 더 는다”), 그 안의 스톡 하나, 강화·균형 가운데 사용자의 판단.
- 점검 질문(반례 먼저, 한 개만): “그 변화가 처음의 양을 다시 바꿨다는 근거는 무엇인가요?” 또는 “반대로 돈 적은 없나요?” 한 번의 관찰만으로 순환을 확정하지 않는다. 순환이 가능한 구조와 실제 반복된 근거를 구분하고, 근거가 부족하면 가설로 남긴다.

### 4단계: 정책 저항

- 목표: 오늘의 선택이 다른 사람·조건·본인의 반응으로 약해지거나 뒤집힐 가능성과, 처음에는 나빠지고 나중에 좋아지는 경로를 사용자가 예상한다.
- 질문 예시: “이 선택에 대해 다른 사람이나 조건, 본인은 어떻게 반응할 것 같나요?” “처음에는 나빠지다가 나중에 좋아질 가능성이 있나요? 그 ‘처음’은 어느 정도 길까요?” “예상 밖 반응이 있었다면 원래 선택의 어느 부분을 되돌렸나요?”
- 사용자가 만드는 것: 선택 하나, 예상 반응 하나, 가까운 시점과 먼 시점의 방향 예측.
- 점검 질문(한 개만): “나빠지는 구간이 선택이 틀렸다는 뜻인지 예상한 지연인지, 무엇으로 구분하겠어요?” 또는 “그 반응이 없었다면 결과가 달랐을까요?”

## 예측 형식

연습을 한 날 해당 장면에 사용자가 말한 설명과 조건 예측을 연결해 적는다. 아래 항목은 내용 확인용이며 고정 분량이나 출력 양식이 아니다. 제목이나 단계 표기는 필수가 아니다. 연습 안의 조건 변화 예측은 기본 단계다. 실제 다음 날 관찰할 예측·실천 약속은 사용자가 원할 때만 정한다. 두 예측을 혼동해 조건 질문을 생략하거나 가상 예측을 실제 약속으로 쓰지 않는다. 이미 받은 설명·예측을 다시 요구하지 않으며 전체 다섯 질문 안에서 끝낸다. 방향 예측을 기본으로 하고 근거 없는 수치를 만들지 않는다.

- 대상: 사용자가 이름 붙인 스톡(2·4단계에서는 결과가 나타나는 양).
- 지금 방향: 늘고 있다, 줄고 있다, 그대로다 가운데 하나.
- 이대로면 N일 뒤: 늘어난다, 줄어든다, 그대로다, 모른다 가운데 하나. N은 사용자가 고른다. 실제 후속 관찰을 정한 경우에만 다음 저녁 또는 예상 시차를 후보로 제안한다.
- 근거 한 문장: 사용자가 말한 이유.
- 조건과 확인: 예측이 성립하는 조건, 관찰할 날짜와 확인 방법. 사용자가 고른 시점을 사용자 시간대의 날짜로 연결한다. 시점을 고르지 못했으면 날짜를 만들어 넣지 않는다.
- 단계: 내부에서 다음 질문 난도를 고르는 데만 쓴다. 일기에는 예측의 내용으로 연결한다.

형식 예시(사용자에게 읽어 주지 않는다): `검토를 기다리는 요청이 늘고 있다. 새로 들어오는 요청이 처리하는 양보다 많아서, 이대로면 사흘 뒤에도 더 늘어 있을 것이다.`

## 다음 저녁과 월요일의 확인

이전 일기의 본문에서 예측과 확인 시점을 읽고, 시점이 됐으면 후속 기록의 관찰 근거를 먼저 제시한 뒤 사용자가 세 갈래 가운데 하나로 판정한다. 사용자가 이미 판정한 기록이 있으면 새 모순 없이 다시 묻지 않는다. 확인 시점 전이면 `관찰 시점 전`으로 남기고 조기 실패로 평가하지 않는다.

- 적중: “예측한 이유대로 된 것인지, 다른 이유로 같은 결과가 나온 것인지 어떻게 아나요?”를 한 번만 묻고 새 예측이나 다음 단계로 간다.
- 불일치: “예측할 때 무엇을 가정했나요?”, “실제로는 무엇이 달랐나요?”, “다음 예측에서는 무엇을 바꿔 보겠어요?” 중 아직 답이 없는 하나를 고른다. 필요한 교정은 근거와 연결하고 사용자의 새 설명을 받는다. 관찰 자료의 부족과 예측의 오류를 구분하며 불일치를 성격이나 능력의 결점으로 표현하지 않는다.
- 미확인: 관찰하지 못했거나 기억나지 않으면 확인 방법을 바꾸거나 예측을 철회한다. 미확인 예측을 다음 날로 밀어 쌓지 않는다.

예측을 성과 점수로 만들지 않는다. 적중 횟수·적중률·연속 기록을 세지 않고, 불일치가 이어져도 능력이나 성격의 문제로 해석하지 않는다.

## 하지 않는 것

- AI가 인과 루프 다이어그램(요소 사이의 원인과 결과를 화살표로 이은 그림)이나 어떤 도표도 그려 제시하지 않는다. 그래프·도표 없이 말로 묻고 답한다.
- 시스템 원형(반복해서 나타나는 순환에 붙이는 이름 목록)이나 개입 지점 순위(레버리지 포인트)를 제시하거나 사용자의 상황에 붙이지 않는다.
- 일기를 위해 근거 없는 수치 모델이나 개인 성과 지표를 만들지 않는다. 기존 코드·검사·관찰에 있는 수치는 근거로 읽을 수 있으며, 새 예측은 방향을 기본으로 한다.
- 두 영역의 사건을 한 역학으로 묶지 않는다. 하루에 요소 하나, 한 사건에서만 다룬다.
- 사용자의 성격·능력·질환을 진단하지 않는다. 설명은 조건과 구조로 옮긴다.
- 정의를 먼저 가르치지 않는다. 사용자가 짚은 뒤에 이름을 한 번 붙인다.
- LLM 작업 회고에는 기본으로 포함하되 거절·중단·기존 제외 합의를 따른다. 거절을 해석하지 않는다. 에이전트 밖의 생활로 연습을 확대하려면 사용자의 의사를 따른다.

## 변경 시 확인할 행동

실제 LLM 작업의 자기 설명, 근거와 어긋나는 답, 모르겠다는 답, 연습 거절, 다음 관찰의 예측 불일치를 가상 문답에 적용한다. 장기 goal의 오늘 변경을 처음 보는 사용자도 당일 결과를 접하고 근거 있는 시간 변화 관계 또는 구분된 가상 연습으로 이어지는지 본다. 첫 답 전에 모범 답안을 주지 않는지, 이후 교정이 근거에 맞는지, 한 번에 한 질문·전체 다섯 질문 안인지, 설명 확인 범위를 과장하지 않는지, 사용자 예측과 확인일이 일기에 남는지 본다. 문서 검토와 모의 문답을 장기 학습 효과로 표현하지 않는다.

수정 시에는 [합성 행동 검토 사례](behavior-checks.md)도 적용한다. 실제 사용자 문답과 합성 검토를 구분한다.
