# 역학 연습 진행표

`SKILL.md` 4절에서 사용자가 역학 연습을 요청했거나 기존 합의가 있거나 한 문장 제안을 받아들인 날에만 읽는다. 연습을 시작하는 날에는 "용어"와 "진행표"의 현재 단계 절, "예측 형식"을 읽고, 다음 저녁에 이전 예측을 확인할 때는 "다음 저녁의 확인"만 읽는다. 매일 전체를 다시 읽지 않는다.

역학 연습은 오늘의 사건 하나에서 시간이 지나며 쌓이거나 줄어드는 양과 그것을 움직이는 것, 행동과 결과 사이의 시차, 변화가 스스로를 키우거나 되돌리는 순환 가운데 하나를 사용자가 자기 말로 짚어 보는 약 3분의 문답이다. 하루에 요소 하나만 다루고 질문은 다섯 개를 넘기지 않는다. AI는 요소를 대신 찾아 주거나 정답을 설명하지 않고 질문과 사용자의 답으로만 진행한다. 이 연습이 이해력을 높인다는 직접 증거는 없으며, 효과는 다음 저녁의 예측 확인과 사용자 본인의 판단으로만 본다. 근거와 한계는 [출처와 설계 범위](design-sources.md)의 "역학 연습의 근거와 한계" 절에 있고, 스킬을 수정할 때만 읽는다.

## 용어

이 문서 안에서 쓰는 이름이다. 사용자 앞에서는 오른쪽 열의 말로 묻고, 사용자가 요소를 자기 말로 짚은 뒤에 “이 연습에서는 그것을 스톡이라 부릅니다”처럼 한 번만 이름을 붙인다. 정의를 먼저 가르치지 않는다.

| 이름 | 뜻 | 사용자에게 묻는 말 |
|---|---|---|
| 스톡 | 시간이 지나며 쌓이거나 줄어드는 양. 어느 시점에 얼마나 있는지 말할 수 있다 | “시간이 지나면서 쌓였거나 줄어든 것” |
| 플로우 | 일정 기간 동안 스톡을 늘리거나 줄이는 양 | “그것을 늘린 일과 줄인 일” |
| 지연 | 행동과 그 결과가 보이기까지의 시차 | “결과가 언제쯤 보일지” |
| 강화 루프 | 변화가 같은 방향의 변화를 더 키우는 순환 | “늘어나자 더 늘리는 일이 생겼는지” |
| 균형 루프 | 변화를 어떤 수준으로 되돌리는 순환 | “늘어나자 줄이는 일이 생겼는지” |
| 정책 저항 | 선택이 다른 사람·조건·본인의 반응으로 약해지거나 뒤집히는 일 | “이 선택에 무엇이 어떻게 반응할지” |
| 멘탈 모델 | 상황이 어떻게 움직이는지에 대해 사용자가 머릿속에 갖고 있는 설명 | (직접 쓰지 않는다) |
| 상관 휴리스틱 | 들어오는 양의 오르내림이 쌓인 양의 오르내림과 같을 것이라고 짐작하는 습관. 들어오는 양이 줄어도 나가는 양보다 많으면 쌓인 양은 계속 는다 | (직접 쓰지 않는다. 점검 질문으로만 다룬다) |

## 진행표

사용자가 원할 때만 다음 단계로 간다. 조건을 채웠어도 같은 단계를 더 하고 싶으면 머문다. 단계는 이전 일기의 `오늘 본 역학` 항목에 적힌 단계 표기로 이어 가고, 이전 일기를 읽을 수 없으면 사용자에게 어느 단계였는지 묻는다. 모르면 1단계부터 한다.

| 단계 | 요소 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1 | 스톡과 플로우 | 스톡과 플로우를 구분해 말했고, 예측을 두 번 이상 다음 저녁에 확인했으며, 사용자가 다음을 원한다 |
| 2 | 지연 | 시차가 있는 예측을 한 번 이상 확인했고, 사용자가 다음을 원한다 |
| 3 | 순환 | 순환 안의 스톡을 짚었고 반례를 확인했으며, 사용자가 다음을 원한다 |
| 4 | 정책 저항 | 마지막 단계다. 반복하거나 1단계로 돌아가 다른 스톡을 고른다 |

### 1단계: 스톡과 플로우

- 목표: 오늘 사건 하나에서 쌓이거나 줄어든 양 하나와 그것을 늘린 것·줄인 것을 사용자가 자기 말로 짚는다.
- 질문 예시: “오늘 이 일에서 시간이 지나면서 쌓였거나 줄어든 것이 있나요?” “그것을 늘린 일과 줄인 일은 각각 무엇이었나요?” “지금 그 양은 어제보다 많은가요, 적은가요, 비슷한가요?”
- 사용자가 만드는 것: 스톡의 이름 하나(사용자 표현), 늘리는 것 하나, 줄이는 것 하나, 지금 방향.
- 점검 질문(한 개만): “늘리는 일이 줄어들면 쌓인 양도 바로 줄어드나요, 아니면 한동안 더 늘 수 있나요?” 또는 “쌓인 양이 줄기 시작하려면 무엇이 무엇보다 커져야 하나요?” 사용자가 “들어오는 것이 줄면 바로 준다”고 답하면 오늘 사건에서 반례가 있었는지 묻는다. 정답을 말하지 않는다.

### 2단계: 지연

- 목표: 오늘 한 행동과 그 결과 사이의 시차를 사용자가 짚고, 시차 때문에 달라진 판단을 살핀다.
- 질문 예시: “오늘 한 그 선택의 결과는 언제쯤 보일 것 같나요?” “지금 보이는 결과는 언제 한 행동에서 온 것인가요?” “결과가 아직 안 보인다는 것을 오늘 어떻게 해석했나요?”
- 사용자가 만드는 것: 행동 하나, 기대하는 결과 하나, 예상 시차(며칠 안·몇 주 뒤·모름 가운데 하나), 그 시차 동안 할 일.
- 점검 질문(한 개만): “결과가 보이기 전까지 같은 행동을 계속 늘리면 결과가 보일 때 어떻게 될까요?” 또는 “아직 결과가 없다는 것과 효과가 없다는 것은 어떻게 구분하나요?”

### 3단계: 순환

- 목표: 오늘 사건에서 변화가 스스로를 키웠는지(강화 루프) 어떤 수준으로 되돌렸는지(균형 루프) 한 순환을 사용자가 말로 서술하고, 그 안에서 쌓이는 것을 짚는다.
- 질문 예시: “그 양이 늘어나자 그것을 더 늘리는 일이 생겼나요, 줄이는 일이 생겼나요?” “그 순환에서 쌓이는 것은 무엇인가요?” “그 순환을 멈추거나 되돌린 것이 있었나요?”
- 사용자가 만드는 것: 두 요소 이상의 순환 한 개를 한 문장으로(“A가 늘면 B가 늘고, B가 늘면 A가 더 는다”), 그 안의 스톡 하나, 강화·균형 가운데 사용자의 판단.
- 점검 질문(반례 먼저, 한 개만): “그 순환이 어제도 있었나요, 오늘 한 번 있었나요?” 또는 “반대로 돈 적은 없나요?” 한 번 있었던 일은 순환으로 부르지 않는다. 사용자가 순환에 스스로 이름을 붙이면 그 이름의 맞고 틀림을 판정하지 않고 구성 요소와 스톡을 묻는다.

### 4단계: 정책 저항

- 목표: 오늘의 선택이 다른 사람·조건·본인의 반응으로 약해지거나 뒤집힐 가능성과, 처음에는 나빠지고 나중에 좋아지는 경로를 사용자가 예상한다.
- 질문 예시: “이 선택에 대해 다른 사람이나 조건, 본인은 어떻게 반응할 것 같나요?” “처음에는 나빠지다가 나중에 좋아질 가능성이 있나요? 그 ‘처음’은 어느 정도 길까요?” “예상 밖 반응이 있었다면 원래 선택의 어느 부분을 되돌렸나요?”
- 사용자가 만드는 것: 선택 하나, 예상 반응 하나, 가까운 시점과 먼 시점의 방향 예측.
- 점검 질문(한 개만): “나빠지는 구간이 선택이 틀렸다는 뜻인지 예상한 지연인지, 무엇으로 구분하겠어요?” 또는 “그 반응이 없었다면 결과가 달랐을까요?”

## 예측 형식

연습을 한 날 일기의 `**오늘 본 역학:**` 항목에 사용자 말로 한두 문장으로 적는다. 예측은 “이대로 가면 며칠 뒤에는 어떻게 되어 있을까요? 며칠 뒤로 볼까요?”처럼 한 번 묻고 사용자의 말로 받는다. 이 질문도 다섯 개 안에 든다. 수치가 아니라 방향이다. 표로 만들지 않는다.

- 대상: 사용자가 이름 붙인 스톡(2·4단계에서는 결과가 나타나는 양).
- 지금 방향: 늘고 있다, 줄고 있다, 그대로다 가운데 하나.
- 이대로면 N일 뒤: 늘어난다, 줄어든다, 그대로다, 모른다 가운데 하나. N은 사용자가 고른다. 기본은 다음 저녁이고 2단계에서는 예상 시차를 쓴다.
- 근거 한 문장: 사용자가 말한 이유.
- 단계 표기: `(1단계)`처럼 짧게. 다음 저녁에 단계를 이어 가기 위한 것이며 점수가 아니다.

형식 예시(사용자에게 읽어 주지 않는다): `**오늘 본 역학:** (1단계) 검토를 기다리는 요청이 늘고 있다. 새로 들어오는 요청이 처리하는 양보다 많아서, 이대로면 사흘 뒤에도 더 늘어 있을 것이다.`

## 다음 저녁의 확인

이전 일기에 예측이 있으면 사용자가 세 갈래 가운데 하나로 판정한다. AI가 판정하지 않는다.

- 적중: “예측한 이유대로 된 것인지, 다른 이유로 같은 결과가 나온 것인지 어떻게 아나요?”를 한 번만 묻고 새 예측이나 다음 단계로 간다.
- 불일치: 사용자가 멘탈 모델을 고친다. “예측할 때 무엇을 가정했나요?”, “실제로는 무엇이 달랐나요?”, “다음 예측에서는 무엇을 바꿔 보겠어요?” 순서로 묻고 사용자의 새 설명을 자기 말로 받는다. 불일치를 실패나 결점으로 표현하지 않는다. AI가 맞는 구조를 설명하지 않는다.
- 미확인: 관찰하지 못했거나 기억나지 않으면 확인 방법을 바꾸거나 예측을 철회한다. 미확인 예측을 다음 날로 밀어 쌓지 않는다.

예측을 성과 점수로 만들지 않는다. 적중 횟수·적중률·연속 기록을 세지 않고, 불일치가 이어져도 능력이나 성격의 문제로 해석하지 않는다.

## 하지 않는 것

- AI가 인과 루프 다이어그램(요소 사이의 원인과 결과를 화살표로 이은 그림)이나 어떤 도표도 그려 제시하지 않는다. 그래프·도표 없이 말로 묻고 답한다.
- 시스템 원형(반복해서 나타나는 순환에 붙이는 이름 목록)이나 개입 지점 순위(레버리지 포인트)를 제시하거나 사용자의 상황에 붙이지 않는다.
- 수치 모델이나 정량화를 하지 않는다. 예측은 방향이다.
- 두 영역의 사건을 한 역학으로 묶지 않는다. 하루에 요소 하나, 한 사건에서만 다룬다.
- 사용자의 성격·능력·질환을 진단하지 않는다. 설명은 조건과 구조로 옮긴다.
- 정의를 먼저 가르치지 않는다. 사용자가 짚은 뒤에 이름을 한 번 붙인다.
- 연습을 설득하지 않는다. 요청이나 합의가 없으면 `SKILL.md` 4절에서 한 문장으로 한 번만 제안하고, 거절하면 그날은 다시 권하지 않으며 거절을 해석하지 않는다.

## 변경 시 확인할 행동

1단계 정상 흐름, 사용자가 연습을 거절하는 경우, 다음 저녁에 예측이 불일치한 경우를 가상 문답에 적용해 본다. 질문이 한 번에 하나인지, AI가 요소를 대신 찾거나 정답을 설명하지 않았는지, 용어를 사용자 식별 뒤에만 붙였는지, 질문 다섯 개 안에 끝나는지, 예측이 방향과 사용자 근거로 적혔는지, 두 영역을 묶지 않았는지, 불일치를 점수나 결점으로 만들지 않았는지 본다. 문서에 효과를 주장하는 문장이 들어가지 않았는지 확인한다.
