# 상황별 질문 예시

질문 목록을 순서대로 읽지 않는다. 사용자 답에서 아직 불분명한 한 가지만 고르고, 아래 가설과 맞지 않으면 해당 축을 버린다. 예시의 보완 행동은 사용자가 선택하기 전까지 제안이다.

## 근거를 더 모으고 싶었던 날

- “추가로 확인한 내용 때문에 실제로 달라진 판단이 있었나요?”
- 필요하면 다음 답에서 “그 검증을 생략했다면 놓쳤을 구체적인 위험은 무엇인가요?”를 묻는다.
- 충분한 검증은 강점이다. 추가 확인의 비용이 컸다는 사용자 설명이 있을 때만, 결정을 바꾸는 근거와 종료 기준을 미리 적는 행동을 제안한다. 위험한 작업의 검증을 임의로 줄이라고 하지 않는다.

## 준비·도구 정비가 많았던 날

- “오늘 준비한 것 중 실제 문제를 해결하거나 다음 행동을 쉽게 만든 것은 무엇인가요?”
- “준비가 필요했던 조건과 지금 바로 해볼 수 있었던 일은 어떻게 달랐나요?”
- 시스템 정비를 미루기로 단정하지 않는다. 사용자가 직접 실행 시간이 줄었다고 느끼면 새 체계를 만들기 전에 실제 문제 하나를 짧게 해보는 선택을 제안한다.

## AI와 함께 결과를 완성한 날

- “이 결과에서 본인이 설명할 수 있는 판단 하나는 무엇인가요?”
- 학습 확인을 원하면 “조건 하나가 바뀐다면 무엇이 달라질까요?”를 답변에 맞게 구체화한다.
- 공동 결과와 독립 이해의 차이는 확인할 대상이다. 도움받았다는 이유만으로 이해 부족을 단정하지 않는다. 필요한 경우 다음 날 한 부분을 도움 없이 시도하고 비교하는 행동을 제안한다.

## 목표나 평가 지표가 바뀐 날

- “오늘 중요하게 본 기준이 처음 원했던 결과와 어떻게 연결되나요?”
- “그 기준에는 담기지 않았지만 지키고 싶었던 것은 무엇인가요?”
- 목표 수정은 새로운 근거에 대한 적절한 대응일 수 있다. 초점 분산을 사용자가 확인했다면 다음 작업의 끝낼 결과 한 문장과 나중에 할 일 하나를 분리하는 선택을 제안한다.

## 결정·위임이 어려웠던 날

- “직접 결정해서 지킬 수 있었던 것은 무엇인가요?”
- “그 선택이 마음에 들지 않을 때 되돌리는 데 무엇이 필요했나요?”
- 통제욕을 추정하지 않는다. 사용자가 부담을 느꼈고 되돌릴 수 있는 선택이면, 다음에는 작은 범위와 되돌릴 조건을 정해 맡기는 행동을 제안한다.

## 에이전트 밖에서 힘들었거나 편안했던 날

- “그 순간에 가장 필요했던 것은 무엇인가요?”
- “그때의 조건에서 가능했던 선택은 무엇이었나요?”
- “오늘 그대로 유지하고 싶은 순간은 무엇인가요?”
- 휴식·관계·몸 상태를 개발 성과의 원인으로만 해석하지 않는다. 충분히 쉰 날은 고칠 점 없이 기록할 수 있다. 작게 쉬기, 경계 표현하기, 도움 요청하기, 즐거운 활동 유지하기도 다음 선택이 된다.

## 피곤하거나 기록이 부족한 날

코딩 에이전트와 함께 한 일 중 기억나는 것 하나와 에이전트 밖에서 마음에 남은 일 하나를 각각 짧게 묻는다. 이미 답한 영역은 다시 묻지 않는다. 사용자가 생략하거나 마무리를 요청하면 확인된 장면으로 짧은 일기를 쓴다. 추정한 감정·해석·실천을 끼워 넣지 않는다.
